VRCFury 工具通用安装触发流程：Gesture Manager Emulator 进 Play Mode 五步安装法

任何 VRCFury 驱动的非破坏性工具（GoGo Loco、SPS、VRCFury Toggle、Full Controller 等）都遵循同一套安装触发流程：导入资源包后必须在 Unity Play Mode 中完成安装，而不是像传统 Unity Asset 那样拖入场景后直接使用。

五步通用工作流：

  1. 导入资源包：将工具的 .unitypackage 拖入 Unity 项目。
  2. 拖入预设体：将工具的 Prefab（如 GoGo Loco 预设体、SPS 工具预设等）拖入 Avatar 子集。
  3. 打开触发器：菜单 Tools > Gesture Manager Emulator 打开 Inspector 窗口。
  4. Enter Play-Mode：点击 Inspector 窗口中的 Enter Play-Mode 按钮。
  5. 完成安装：VRCFury 在 Play Mode 中执行非破坏性安装，完成后 Avatar 即配置完毕。

与传统 Unity Asset 流程的差异：传统资产导入并拖入场景后即可直接使用；VRCFury 工具则必须额外执行 Enter Play-Mode 触发安装，期间可能弹出 Auto-Fix 兼容性确认窗口，点击确认即可。

前置条件：必须先通过 VCC（Manage Your Project）安装 Gesture Manager 插件与 VRCFury 自身，缺一不可。

适用性已验证：GoGo Loco 1.8.3、SPS、VRCFury Toggle、VRCFury Full Controller 均遵循此流程。

溯源：VRCFury 官方文档（v1.1341.0+ (2026-06-16)）；证据级 official。

VRCFury 三大设计原则：非破坏性、Play Mode 触发、Auto-Fix 容错及与传统流程对比

VRCFury 的全部行为可以用三大设计原则解释，排查问题时应先对照这三条：

  1. Non-Destructive（非破坏性）：原始 Avatar 资产不被修改。实现方式是在 Play Mode 中以临时数据形式生成配置，上传前才复制应用。
  2. Play Mode 触发：仅在 Play Mode 中执行安装。实现方式是利用 Unity Play Mode 的运行时 API 访问 Avatar 3.0 系统。
  3. Auto-Fix 容错：自动修复配置问题。配置过程中检测到冲突时弹出 Auto-Fix 弹窗一键修复。

与传统 Unity Asset 模式的逐项对比：修改时机——传统在 Edit Mode 直接修改资产，VRCFury 在 Play Mode 临时生成；原始资产——传统被直接改动，VRCFury 不修改（上传前复制）；配置位置——传统持久化在场景里，VRCFury 持久化在 Avatar 内（Play Mode 结束后仍保留）；可回滚性——传统回滚困难需手动撤销，VRCFury 删除 Prefab 即可整体回滚。

溯源：VRCFury 官方文档（v1.1341.0+ (2026-06-16)）；证据级 official。

VRCFury 为何必须在 Play Mode 中安装：运行时 API 访问与临时数据生成原理（工程推断）

【工程推断，非官方明确说明】VRCFury 选择只在 Play Mode 中执行非破坏性安装，原因有三：

  1. 运行时 API 访问：只有 Play Mode 中才能访问 Avatar 3.0 的运行时数据（Animator Runtime Controller、PlayableGraph 等），Edit Mode 下这些对象不可用。
  2. 临时数据生成：Play Mode 中生成的配置以临时数据形式存在、不写入磁盘，天然保证原始资产不被修改。
  3. Edit Mode 限制：如果在 Edit Mode 中直接修改 Animator Controller 等资产文件，会破坏原始资产，直接违反 Non-Destructive 原则。

因此“必须进 Play Mode 才生效”不是缺陷或多余步骤，而是非破坏性架构的必然代价：想要不改原始文件，就只能借助运行时临时数据完成装配。

溯源：工程推断（多案例交叉验证）（v1.1341.0+ (2026-06-16)）；证据级 inferred。

VRCFury Auto-Fix 容错机制：兼容性弹窗触发场景与一键自动修复方式

VRCFury 在配置过程中检测到问题时会弹出兼容性提示窗口，点击窗口左下角的 Auto-Fix 按钮即可自动修复，一般无需手动干预。

常见触发场景有三类：Animator Controller 冲突、Parameter 名称冲突、VRCFury 组件版本不兼容。

处理方式：看到兼容性提示窗口后直接点左下角 Auto-Fix，等待自动修复完成即可。遇到 Auto-Fix 弹窗属于正常安装流程的一部分，不代表安装失败，不需要回滚重装或手工修改控制器。

溯源：VRCFury 官方文档（v1.1341.0+ (2026-06-16)）；证据级 official。

VRCFury 配置持久化规则：退出 Play Mode 后配置保留、重开项目无需重复触发

VRCFury 在 Play Mode 中完成的安装是一次性的持久配置：退出 Play Mode 后配置仍保留在 Avatar 上，以 VRCFury 生成的非破坏性形式存储。

由此得到两条使用规则：其一，重新打开项目时不需要也不应该期待 Play Mode 自动触发——只有在首次配置或修改预设体（Prefab）之后才需要再次进入 Play Mode 触发安装；其二，想撤销整套配置时删除对应的 Prefab 即可，无需手动清理场景或控制器。

VRCFury 主要组件清单：Toggle、Gestures、Full Controller、Armature Link、Global Collider 与 MA 对应关系

VRCFury 主要组件及其与 Modular Avatar（MA）的对应关系如下：

选型参考：Toggle、Full Controller、Armature Link 属于 MA 已覆盖或部分覆盖的功能，两者二选一即可；Gestures 与 Global Collider 是 VRCFury 明显更省事的场景。

VRCFury 优化组件清单：Parameter Compressor、Direct Tree Optimizer、Blendshape Optimizer、Fix Write Defaults

VRCFury 内置四个优化组件，覆盖同步参数、Animator 层数、VRAM、Write Defaults 四个性能维度：

  • Parameter Compressor（⭐ 核心优化）：压缩同步参数。原理是将所有菜单控制的 Float/Int 参数压入 16 bit；实测效果为同步占用从 253 bit 降到 125 bit。
  • Direct Tree Optimizer（⭐ 核心优化）：减少 Animator 层数。原理是将非冲突层合并为单个 Direct Blend Tree 层；效果是显著减少 frametime。
  • Blendshape Optimizer（⭐ 核心优化）：减少 VRAM 占用。原理是烘焙所有非动画 BlendShape 到 Mesh；效果是零成本减少 VRAM。
  • Fix Write Defaults：修复 WD 冲突。原理是自动检测并对齐所有动画状态的 WD 设置；效果是消除 WD 混合导致的 bug。

排查 Avatar 性能等级过高或 frametime 异常时，优先检查这四个组件是否已启用。

溯源：VRCFury 官方文档（v1.1341.0+ (2026-06-16)）；证据级 official。

SPS (Super Plug Shader) 简介与核心优势：免费开源 DPS/TPS 替代变形系统、兼容 Shader 与 Socket 数量限制

SPS（Super Plug Shader）是 VRCFury 提供的免费变形 Shader 系统，定位为 DPS/TPS 的替代品。

基本属性：类型为免费变形 Shader；兼容 Poiyomi Toon/Pro 7/8+、lilToon、UTS、Mochie、XSToon、Silent、Standard 等主流 Shader；支持 Rigged 与 Un-rigged Mesh、BlendShape 动画、Avatar Scaling；向后兼容所有 TPS 和 DPS 系统；数量限制为最多 2 Socket 加无限 Plug，附近有 Point Light 时 Socket 上限降至 1。

SPS Plug 设置流程：Create Plug 创建、骨骼/Mesh Renderer 绑定规则与直线展开基准约束

SPS Plug 代表形变的主动方，通过菜单 Tools > VRCFury > SPS > Create Plug 创建，设置要点是绑定对象、基部位置与伸展方向。

设置步骤：第一步走菜单路径 Tools > VRCFury > SPS > Create Plug 创建；第二步绑定网格——有骨骼的网格将 Plug 拖到形变区域底部的骨骼子集上，无骨骼的网格将 Plug 拖到形变区域的 Mesh Renderer 上；第三步将 Plug 定位到形变区域的底部/基部；第四步旋转 Plug 使其弯曲端对齐形变区域尖端所指的方向。

关键约束：Plug 在编辑器中必须保持完全伸直（fully extended）状态，这是形变的基准方向；编辑器里弯曲摆放会导致形变基准错误。

例外（静态弯曲）：若需要 Avatar 静止时 Plug 呈弯曲或不展开的外观，不要直接弯折 Plug，而是在 Plug 组件的 Post-Bake Actions 字段添加动画来实现。

溯源：VRCFury 官方文档（v1.1341.0+ (2026-06-16)）；证据级 official。

SPS Socket 设置流程：Create Socket 创建、箭头朝内定向与双灯 Very Poor 性能警告

SPS Socket 代表承接形变的被动方，通过菜单 Tools > VRCFury > SPS > Create Socket 创建，设置要点是目标骨骼、接触点位置与箭头朝向。

设置步骤：第一步走菜单路径 Tools > VRCFury > SPS > Create Socket 创建；第二步将 Socket 拖到目标骨骼上；第三步定位到预期接触点；第四步旋转使箭头指向内部空间（朝向身体内部）。

性能警告：单个 Socket 包含 2 个 lights 时，Avatar 性能等级会直接降为 Very Poor——即使禁用的灯不消耗实际渲染性能也一样触发评级惩罚，因此每个 Socket 应只保留 1 组灯。

关联限制：Socket 附近存在 Point Light 时，SPS 的 Socket 数量上限会从 2 降到 1。

溯源：VRCFury 官方文档（v1.1341.0+ (2026-06-16)）；证据级 official。

VRCFury SPS 不要与 Constraints 混用：重复 socket 失效与触点抖动风险及正确做法

结论：VRCFury 官方专题文档明确警告「DON’T MIX SPS WITH CONSTRAINTS」——SPS 的 Socket 必须直接放在目标骨骼上，不要通过 Constraints 来切换或承载。

混用的具体危害有四点：

  1. OGB 无法检测重复 socket 的触点激活（当多个 socket 共享同一参数名时）。
  2. 重复 socket 不能单独动画化。
  3. 重复 socket 会阻止所有 SPS 菜单功能，包括 Auto mode、Dual mode 等。
  4. Constraints 由于 VRChat bug 会给 contacts 带来大量抖动，导致深度动画和 haptics 异常；此外 Parent constraints 性能略低于直接挂在父级。

正确做法：把 Socket 组件直接放在目标骨骼上，不引入任何 Constraint 中间层。

溯源：VRCFury 官方文档（官方快照验证日期 2026-07-04）；证据级 official。

从 DPS/TPS 迁移到 VRCFury SPS：两条升级工具路径、手动升级步骤与平台级限制

结论：从 DPS/TPS 迁移到 VRCFury SPS 有两条官方工具路径，按范围选择：

工具路径 用途 适用场景
Tools > VRCFury > SPS > Upgrade DPS to SPS 升级整个 Avatar 整体从 DPS 迁移到 SPS
Tools > VRCFury > SPS > Upgrade Legacy Haptics 升级单个对象 为单个 plug/socket 添加 contacts

手动 DPS 升级步骤（不用自动工具时）：

  1. 删除所有 DPS Tip lights（通常在名为 Physics 的子对象里）。
  2. 把 plug 材质的 shader 从 Raliv/Penetrator 改为 Standard 或其他目标 shader。
  3. 删除任何现有的 SPS Plug 组件（若之前运行过 Haptic Upgrader，这些组件常在 mesh renderer 同级）。

手动 TPS 升级步骤：在 Poiyomi material 面板禁用 Penetrator 复选框。

已知迁移副作用：之前用 Fluff’s Toolbox DPS Setup 或 Universal DPS Attachment System 的 Avatar，菜单 toggles 可能会自动移动到新 SPS 文件夹。

平台级限制：存储在 World 中的 plug/socket 无法触发深度动画（没有 contacts），无解决方案；只能让其他玩家安装 VRCFury 并升级其 DPS 来解决。

溯源：VRCFury 官方文档（官方快照验证日期 2026-07-04）；证据级 official。

VRCFury SPS Plug 缩放与动画限制：允许/禁止操作清单、Animated Toggle 条件与加长技巧

结论：SPS Plug 的缩放与动画有一组明确的允许/禁止边界，核心判据是「不能破坏长度语义」。

允许的操作：

  • 对 Plug 的父级对象进行均匀缩放动画。
  • 对 Plug 渲染器的 Blendshape 制作动画，前提：Blendshape 名称已加入 Plug 组件的 Animatable Blendshapes 列表，且不改变 Plug 长度。
  • 在编辑器默认姿态下自由调整位置/旋转/缩放（不影响动画）。

禁止的操作：

  • 对 Plug 渲染器骨骼的位置/旋转/非均匀缩放制作动画（除非骨骼是 Plug 的父级）。
  • 使用影响 Plug 长度的 Blendshape。

生效条件：上述限制仅在 Plug 的 Animated Toggle 启用时生效；关闭 Animated Toggle 后可完全自由控制 Plug 的形变与动画。

加长技巧（不加周长）：①动画中均匀放大整个 Plug 网格；②创建专用 Blendshape 缩小半径以抵消周长增加；③确保该 Blendshape 仅影响径向尺寸、不改变长度。

VRCFury Parameter Compressor 参数压缩器：指针式浮点同步把菜单 Float/Int 参数压进 16 bit

结论：VRCFury Parameter Compressor（参数压缩器）用「指针式浮点同步」技术，把所有菜单控制的 Float 和 Int 同步参数压缩进 16 bit 总同步量，解决 256 bit Expression Parameter 预算不够的问题。

效果对比：传统方式 10 个色相滑块 = 10 × 8 bit = 80 bit；压缩后同样 10 个滑块只需 16 bit（指针 + 数据），节省 64 bit。

技术实现六要素：

  1. 本地化：所有 Radial Puppet 的 Float 参数变为本地参数（不同步）。
  2. 指针 + 数据：用 1 个 Int（指针，8 bit）+ 1 个 Float（数据，8 bit）= 16 bit 同步。
  3. Copy Driver：通过 VRC Avatar Parameter Driver 在数据字段和实际参数之间复制。
  4. 变更检测：用 Blend Tree 数学运算检测哪个参数发生了变化。
  5. 优先级发送：变化的参数优先通过指针发送。
  6. 远程平滑：远端 Avatar 上参数经过平滑处理（因 Copy Driver 丢失了 IK 同步）。

排除规则：非菜单控制参数（可能由 OSC 驱动，如面部追踪）、Two/Four Axis Puppet 参数（尾巴耳朵实时控制）不参与压缩；Parameter Driver 驱动的参数可配置排除，避免与自动驱动冲突。

溯源：VRCFury 官方文档（官方快照验证日期 2026-07-04）；证据级 official。

VRCFury 工具冲突规则：MA Sync Parameter Sequence 不可共存，d4rkAvatarOptimizer 注意先后顺序

结论：VRCFury 与两类常用工具存在明确的兼容性结论——与 MA Sync Parameter Sequence 互斥、不可共存；与 d4rkAvatarOptimizer 可共存，但有执行顺序上的注意事项。

冲突明细：

  1. MA Sync Parameter Sequence（Modular Avatar 的同步参数序列功能）：判定为不可共存。原因在于它与 VRCFury 都会对动画参数槽位进行重排，两套重排流程叠加后无法保证槽位布局正确，FX 参数可能出现错乱。
  2. d4rkAvatarOptimizer（网格优化类插件）：判定为需注意而非禁止。执行顺序上 VRCFury 在 d4rkAvatarOptimizer 之后运行，VRCFury 注入或修改的内容发生在 d4rk 完成优化之后，因此可能影响 d4rk 的优化效果。

实践含义：项目中若已使用 MA Sync Parameter Sequence 管理 FX 参数顺序，应在它与 VRCFury 之间二选一；同时使用 d4rkAvatarOptimizer 时，应在最终上传前完整测试，确认 VRCFury 的后置处理没有破坏 d4rk 已完成的优化。

VRCFury Direct Tree Optimizer 原理：把大量 Toggle 动画层合并成单个 Direct Blend Tree 层减负

结论：VRCFury 的 Direct Tree Optimizer 是减少 FX 动画层数的核心手段——它把所有非冲突的 Animator 层转换为一个 Direct Blend Tree 层，让几十个 Toggle 从各自独占一层变成在同一层内并行处理。

背景原理：VRChat Avatar 的 FX Controller 通常包含大量极简单的 Toggle 层，每层只有 ON/OFF 两个状态。但每个 Animator 层都带有固定计算开销：层权重计算、状态机更新等，层数越多总开销越大，与层内实际内容复杂度关系不大。

转换效果可用官方示例直观表达： 优化前：50 个 Toggle = 50 个 Animator 层（每层独立计算）； 优化后：50 个 Toggle = 1 个 Direct Blend Tree 层（并行计算）。

也就是说，Toggle 数量增长不再带来层数线性增长：无论有多少个符合条件的 Toggle，最终都汇入同一个 Direct Blend Tree，由各自的 Float 权重参数并行驱动。这直接降低了 Animator 的运行时评估开销，是拥有几十上百个开关的大型 Avatar 保持性能的关键优化之一。

溯源：VRCFury 官方文档（版本未标注，工具持续更新）；证据级 official。

VRCFury Direct Blend Tree 技术要素：Direct 混合类型、常量 Weight 1、Bool 转 Float、强制 Write Defaults ON

结论：Direct Tree 优化生成的不是普通的动画层堆叠，而是具有固定技术结构的 Direct Blend Tree；理解这五项要素有助于排查优化后的动画异常。

五项技术要素：

  1. Blend Type：Direct——每个子项（子 Blend Tree）由一个独立的 Float 参数控制其权重，而非依赖时间轴或单一参数插值。
  2. Weight 参数：常量 1——该层总权重固定写 1，不作为同步参数，不占用同步带宽。
  3. Toggle 参数：原本按 Bool 同步的 Toggle 参数会被自动转换为 Float 参数，同步成本仅 1 bit。
  4. Write Defaults：必须 ON——硬性要求，WD 关闭时 Blend Tree 行为会异常。
  5. 动画结构：每个 Toggle 表现为 Direct Tree 下的一棵子 Blend Tree，子树内含 Off 动画与 On 动画两个状态，分别对应该功能的关与开。

排查提示：如果优化后出现动画不复位、状态残留等异常，首先检查相关状态的 Write Defaults 是否被外部工具改成 OFF；VRCFury 自带的 Fix Write Defaults 功能也会把 Direct BlendTree 的 WD 对齐为 On。

溯源：VRCFury 官方文档（版本未标注，工具持续更新）；证据级 official。

Direct Tree 优化适用范围：Toggles/Gestures/SPS 等五类组件自动应用，Animator 层须满足无 Behaviour 双状态互转等五条件

结论：Direct Tree 优化是自动进行的，但只作用于满足严格条件的动画层；掌握适用范围就能预判哪些内容会被减层、哪些不会。

自动应用的组件范围：以下五类 VRCFury 组件生成的动画层会自动套用 Direct Tree 优化，无需额外设置——

  1. Toggles（开关）；
  2. Gestures（手势）；
  3. Full Controllers（完整控制器）；
  4. SPS；
  5. Advanced Visemes（高级口型）。

层级别准入条件：一个 Animator 层必须同时满足以下全部条件，才会被转换为 Direct Blend Tree——

  1. 无 State Behaviour：层内 State 上没有挂任何 Animator Behaviour（脚本类组件）；
  2. 仅两状态：恰好两个 State，对应 ON/OFF；
  3. 互相转换：两个 State 的 Transition 互相指向对方（A→B 与 B→A 同时存在）；
  4. 条件对称：一个 State 的转换条件是另一个的逆（如参数为真 / 参数为假）；
  5. 无冲突属性：该层动画化的属性不与其他层的动画重叠。

排查指引：若某个 Toggle 没有被并入 Direct Tree，逐条对照上述五条件检查——常见原因包括层内挂了 State Behaviour、State 数量超过两个、Transition 未形成互指、或与其他层动画化了相同属性。

溯源：VRCFury 官方文档（版本未标注，工具持续更新）；证据级 official。

VRCFury Blendshape Optimizer：上传时自动烘焙非动画 BlendShape 进基础 Mesh 节省 VRAM

结论：Blendshape Optimizer 用于减少 Avatar 的 VRAM 占用——它自动找出所有从未被动画使用的 BlendShape，把它们的效果直接烘进 Mesh 的基础形状，这些 BlendShape 随即不再占用显存。

为什么要这样做：Avatar Mesh 通常带大量 BlendShape——面部表情、身体微调、体型预设等，其中相当一部分在任何动画里都没有被用到（典型如模型师调体型用的预设滑块）。每个 BlendShape 都要存储一套顶点偏移数据，即使永远不用也持续占用 VRAM。

官方给出的量化示意：优化前 Body Mesh 有 80 个 BlendShape，其中 50 个从未被动画化；优化后 Body Mesh 只剩 30 个 BlendShape，另外 50 个已被烘焙进基础形状，省下了这 50 组顶点偏移数据的显存。

四个关键特性：

  1. 零配置：无需任何设置，自动检测可烘焙项；
  2. 非破坏性：只在上传构建时处理，工程中的原始 Mesh 文件不会被修改；
  3. 安全性：只烘焙确认未被任何动画引用的 BlendShape，被动画用到的绝不触碰；
  4. MMD 兼容：需要保留 MMD 表情时，配合 MMD Compatibility 组件即可把 MMD 相关 BlendShape 保留下来不被烘焙。

VRCFury Fix Write Defaults：自动修复 Additive/DirectTree WD Off、WD 混用与 Missing Animation 四类问题（含四种工作模式）

结论：Write Defaults（WD）设置错误是 Unity/VRChat 模型动画异常的高发原因，VRCFury 的 Fix Write Defaults 组件会自动检测全模型的 WD 状态并按所选模式统一对齐。

四类典型问题与对应处理：

  1. Additive 层 WD 为 Off：后果是 BlendShape 数值被放大 3 倍、无关的 Transform 会持续移动；VRCFury 把这些状态自动标记为 WD On。
  2. Direct BlendTree 中 WD 为 Off：后果是与该树无关的动画出现断裂；同样自动标记为 WD On。
  3. WD On 与 WD Off 混合使用：后果最严重，Unity 会破坏所有动画；VRCFury 检测到混用后自动把状态对齐到一致方向。
  4. Missing Animation（状态缺少动画剪辑）：在 WD Off 场景下会导致 Transform 断裂；VRCFury 用一段空的 1 秒 Clip 替换补位。

四种工作模式：

  • Auto：自动选择需要改动最少的方向（整体 On 或整体 Off）；
  • Force On：强制所有状态 WD On；
  • Force Off：强制所有状态 WD Off；
  • Disabled：不做任何修改。

使用提示：不确定模型 WD 状况时保持 Auto 即可获得安全的自动对齐；由于 Direct Tree 优化要求 WD 必须为 ON，该组件与 Direct Tree 优化是配套关系。

VRCFury 上传前复制机制（All Reversible）：非破坏性构建原理与 Modular Avatar 对比

VRCFury 采用『上传前复制』的非破坏性机制：Avatar 上传时，VRCFury 先复制一份当前状态，在副本上完成全部功能注入后再提交上传，原始动画 Controller 等源文件永远不会被修改。 由此带来三大优势：① 移除 VRCFury 组件后 Avatar 立即恢复原状，天然可逆；② 不影响 TPS、VRCLens 等其他工具已生成的产物；③ 原始动画 Controller 文件永远不被触碰。 实践意义是可以放心试错：不满意就直接删组件回滚，无需提前备份资产，也能在保留原始资产的前提下反复迭代功能配置。 与 Modular Avatar 的对比：MA 直接在 Avatar 上构建 ApplyOnPlay 逻辑，移除 MA 组件后需要手动恢复被改动的内容，没有 VRCFury 这种天然可逆性。

VRCFury 上传时在 Avatar 副本上执行三大优化器且全部可逆（All Reversible）

VRCFury 的所有优化都发生在上传前的 Avatar 副本上，官方明确这一机制为 All Reversible（全部可逆）：你的源工程文件不会被改动，随时可以调整设置后重新生成。 上传时 VRCFury 主要执行三类自动优化：

  1. Parameter Compressor（参数压缩器）：把所有 Float/Int 类型的同步参数压缩到 16 bit，大幅降低参数位占用。
  2. Direct Tree Optimizer（直树优化器）：把满足条件的动画层合并成 Direct Blend Tree（直接混合树），减少运行时动画层数量。
