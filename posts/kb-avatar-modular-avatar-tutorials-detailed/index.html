结论：Modular Avatar 教程深度精读（玩家视角完整版）基于官方教程（modular-avatar.nadena.dev/docs/tutorials），覆盖 6 个教程，定位是「完整精读 + 玩家操作视角转化」而非翻译。[FACT] 每篇教程固定包含四部分：官方原文步骤（忠实摘录关键操作）、玩家视角操作（新手友好、每步 1 动作）、验证步骤（判断这一步是否成功）、常见踩坑（这一步最容易卡在哪里）。[FACT] 适用对象为默认玩家没有或仅有少量 Unity、Animator、Avatars3 基础。[INFERENCE] 叙述语言分层：默认叙述面向新手使用动作化且结论化句式（如「把衣服拖到 Avatar 身上」「你应该看到 X」），避免底层术语；专业叙述使用 NDMF/Animator 机制术语（如「NDMF 在 Generating 阶段执行 Merge Armature pass」「Layer Priority 控制 Animator 合并顺序」「Write Defaults 匹配避免混用 ON/OFF 状态」）。[FACT] 转换触发词为：Animator Layer、Write Defaults、Blend Tree、NDMF、Constraint、Expression Parameter、PhysBone。

教程地图与教学决策表：按玩家诉求/问题选择 MA 教程起点，90% 玩家只需教程 1+3

结论：MA 教程按玩家诉求给出起点映射。[FACT] 核心建议：90% 的玩家只需要教程 1（换装）+教程 3（开关），其他教程遇到具体问题再学。[FACT] 完整学习路径：完全新手=教程 1→教程 3；遇到穿模=教程 1→教程 3→教程 5（形态键联动）；有布料衣服=教程 1→教程 2；想编辑菜单/做小组件=教程 1→教程 3→教程 4→教程 6（可选）。[COMMUNITY] 教学决策表按玩家问题定位：装衣→Setup Outfit；开关菜单→Create Toggle；穿模→Shape Changer+Overdraw；调体型不变形→Blendshape Sync；鞋子陷地→Floor Adjuster（主文档 §7.11）；参数冲突→MA Parameters+Internal（主文档 §7.3）；做衣服卖→教程 4+教程 6；布料衣服→Bone Proxy+Collider；重排菜单→Extract menu。

教程 1 Setup Outfit 装衣流程：拖 Prefab→Setup Outfit→隐藏原衣→Play 验证→可选 Blendshape Sync

结论：用 MA 装现成衣服走 Setup Outfit 流程。[FACT] 6 步操作：把衣服 Prefab 拖到 Avatar 子级→右键衣服根选 Setup Outfit（自动加 Merge Armature）→隐藏 Avatar 自带衣服→Play 模式验证跟动→退出 Play→可选加 Blendshape Sync 链接身体形态键。[FACT] 官方设计原话：‘With Modular Avatar, you don’t need to unpack the original avatar or outfit prefab!’——玩家永远不要手动拆 Prefab，保留 Prefab 完整即可一键升级。[COMMUNITY] 常见失败与修复：菜单无 Setup Outfit（MA 未装/未 Apply，检查 VCC/ALCOM 仓库）；Play 不动（未执行 Setup Outfit）；部分跟动（衣服骨骼名与素体不匹配，改名包含素体骨骼名）；Upload 后不动（GameObject 路径问题，用 Manual Bake Avatar 查最终结果）；形态键不生效（链接的形态键名拼写错）。

Merge Armature 合并机制：同名骨骼共享、独有骨骼移到素体骨骼下、含组件骨骼保留独立；设计哲学为不拆 Prefab

结论：Setup Outfit 的底层机制是 Merge Armature 合并骨骼。[FACT] 官方 ‘What happened’ 描述：自动找到 Armature 下挂 Merge Armature，合并时同名骨骼共享（不复制）、衣服独有骨骼移到对应素体骨骼下、含组件的骨骼保留为单独对象。[FACT] 官方设计原话：‘With Modular Avatar, you don’t need to unpack the original avatar or outfit prefab!’（用 MA 你不需要拆开原本的 Avatar 或衣服 Prefab）。[INFERENCE] 教学含义：玩家永远不要手动拆 Prefab，拆了反而麻烦（升级困难、容易坏），保留 Prefab 完整=一键升级。

教程 1 易错点：菜单无 Setup Outfit/Play 不动/部分跟动/Upload 后不动/形态键不同步的排查与修复

结论：教程 1 的易错点集中在五个环节。[FACT] ①菜单里找不到 Modular Avatar→Setup Outfit：原因是 MA 没装或没 Apply，修复为用 VCC/ALCOM 检查 MA 仓库是否勾选。[FACT] ②Play 模式衣服不动：原因是没执行 Setup Outfit，修复为回到 Step 2 重做。[FACT] ③衣服部分身体跟动、部分不动：原因是衣服骨骼名不匹配，修复为改衣服骨骼名包含素体骨骼名。[FACT] ④Play 能动但 Upload 后不能动：原因是 GameObject 路径问题，修复为用 Manual Bake Avatar 看最终结果。[FACT] ⑤形态键同步不生效：原因是链接的形态键名拼写错误，修复为选形态键时检查名称拼写。

教程 2 布料服装配置：所有 Collider 加 MA Bone Proxy 拖素体同名骨骼，Attachment Mode 自动为 As child; keep position，分别 Blendshape Sync Skirt/Tops

结论：布料衣服的关键是把碰撞体挂到素体骨骼。[FACT] 步骤：多选所有 Collider 对象→一次加 MA Bone Proxy→Target 拖入素体同名骨骼→Attachment Mode 自动变为 ‘As child; keep position’，再对每个 Collider 重复，最后对 Skirt 与 Tops 分别做 Blendshape Sync，Play 验证不穿模。[INFERENCE] 可选高级项：加 Merge Animator 自动化设置（Body blendshape torso_thin=100、elbow_off=0、bra_off=100，disable Cloth）。[FACT] ⚠️ 该自动化会与 Outfit Changer 冲突，需注意。[COMMUNITY] 何时该学：衣服有 Cloth 物理效果、有多个 Collider 对象时；普通硬质衣服教程 1 就够。

教程 2 易错点：布料穿透/Attachment Mode 不变/布料抖动的排查（Bone Proxy 只加 Collider 对象并拖对 Target）

结论：教程 2 的三个易错点都围绕 Bone Proxy 配置。[FACT] ①布料穿透：Target 拖错骨骼，修复为检查 Target 是否为素体同名骨骼（衣服 Hips→素体 Hips）。[FACT] ②Attachment Mode 不自动变：Target 字段为空，先拖 Target 骨骼 Mode 才会自动设置。[FACT] ③布料抖动/异常：Bone Proxy 加在错误对象层级，修复为只对 Collider 对象加、不要加到衣服根。

教程 3 Create Toggle 对象开关：生成 3 组件（Menu Item/Menu Installer/Object Toggle），点 Default 复选框即可预览无需 Play

结论：开关对象用 Create Toggle 一步生成。[FACT] 新建 GameObject 上有 3 个组件：MA Menu Item（菜单项）、MA Menu Installer（菜单装到主菜单）、MA Object Toggle（实际开关逻辑）。[FACT] 在 Object Toggle 点 + 拖入对象，勾选=选中时启用、不勾选=选中时禁用；验证时直接点 Menu Item 的 Default 复选框即可在 Scene 看到物件变化，无需进 Play。[FACT] MA 最友好的设计：不需要进 Play 模式就能预览效果，可降低玩家验证焦虑。[INFERENCE] 教学定位：本文档最重要的教学章节，90% 玩家第一个要学的功能，对应最高频需求（开关衣/配件/发型、切换发型、关闭物理效果）；不要教手动 Animator 方案（官方对教程 6 的回应是 ‘why would you?’）。

教程 3 易错点：无 Create Toggle/Default 没反应/上传无菜单项/多物件开不了的排查（含 MA Parameters+Internal）

结论：教程 3 的四个易错点覆盖从安装到上传。[FACT] ①右键菜单没 Create Toggle：MA 没装，检查 VCC/ALCOM 仓库。[FACT] ②点 Default 没反应：没拖对象到 Object Toggle，回 Step 3。[FACT] ③上传 VRChat 没看到菜单项：Menu Installer 配置问题，检查 Install To 字段（默认装顶级）。[FACT] ④多个物件都开不了：参数冲突，加 MA Parameters + Internal 模式。

教程 4 菜单编辑流程：场景 A 用 Extract menu 把现有菜单转 Hierarchy 对象并重组；场景 B 在小组件上加 Menu Item+Menu Installer

结论：教程 4 教两种菜单用法。[FACT] 场景 A：Extract menu 把现有 Avatar 菜单转成 Hierarchy 对象以便编辑——右键 Avatar→Extract menu，新增 Avatar Menu 对象含顶级菜单项，点子菜单的 ‘extract to objects’ 按钮展开嵌套层级，拖拽重组结构，点 ‘Add menu item’ 加新项；Play 模式用 Quick Menu 验证。[FACT] 场景 B：在小组件上创建 GameObject 并加 MA Menu Installer + MA Menu Item，Type 选 Toggle 或 Sub Menu，Parameter 用 ▼ 搜索已注册参数；子菜单用 Submenu Source=Children 并给子级各加 Menu Item。[COMMUNITY] 易错点：提取后菜单『消失』是数据转成对象（备份可恢复）；多个 Is Default 冲突时 MA Parameters 只保留一个 Is Default；参数搜不到说明父级没有 MA Parameters（在 Avatar 根注册）；菜单不显示检查 Installer enabled。

教程 4 高级用法：Parameter Search 自动列出父级 MA Parameters 参数避免手写拼错；Menu Group 让 Installer 装多个 Item 而不建子菜单

结论：教程 4 的两个高级特性改善菜单编辑体验。[FACT] Parameter Search：点参数名旁 ▼ 会搜索所有父级 MA Parameters 组件并自动列出可用参数名，不用手写（容易拼错）。[FACT] Menu Group：同一对象加 MA Menu Installer + MA Menu Group，Installer 可装多个 Item 而不创建 Sub Menu，这是 Extract Menu 系统内部重建菜单的方式。[COMMUNITY] 局限：参数搜不到时先确认父级存在 MA Parameters 组件（在 Avatar 根添加注册）。

教程 4 易错点：菜单消失/多个 Is Default 冲突/参数搜不到/菜单不显示的排查

结论：教程 4 的四个易错点覆盖提取与显示。[FACT] ①Extract menu 后菜单『消失』：菜单数据本身没丢，只是转成了对象，备份可恢复。[FACT] ②多个 Is Default 项冲突：多个菜单项默认选中，MA Parameters 里只保留一个 Is Default。[FACT] ③参数搜不到：没在父级加 MA Parameters 组件，在 Avatar 根加 MA Parameters 注册参数。[FACT] ④菜单不显示：Menu Installer 没启用，检查 Installer 组件 enabled。

教程 5 高级开关流程：形态键全归 0→加 Shape Changer（Target Renderer+Delete 模式）→Overdraw 调试→建子菜单

结论：教程 5=教程 3+形态键联动，官方示例为开关鞋子时同时缩袜子形态键避免穿模。[FACT] 步骤：观察穿模→把两个 shrink 形态键全部重置为 0→鞋子对象加 Shape Changer（Target Renderer 拖被遮挡层、模式 Delete、性能更好直接删多边形）→袜子对象重复→用 Overdraw 调试（Scene 视图→Shaded→Overdraw，半透明透视看穿模）→创建包子菜单加开关项。[FACT] ⚠️ 形态键联动效果在编辑器无法预览，须用 Avatar 3.0 Emulator 或 Gesture Manager 在 Play 模式测试（限制将在未来版本改进）。[COMMUNITY] 常见失败：编辑器预览不到（走 Emulator/Gesture Manager）、Overdraw 没反应（切换 Shaded→Overdraw）、缩错部位（形态键选错重选）、性能变差（Set 改 Delete）。

Shape Changer 模式对比：Delete 删多边形性能好不可动画（默认 90% 情况），Set 设指定值保留多边形可被动画修改

结论：Shape Changer 的两种模式按「是否会被动画修改」二选一。[FACT] Delete=直接删除多边形，性能好、不可动画，用于没有动画控制这个对象的场景（90% 情况）。[FACT] Set=设置形态键为指定值，保留多边形、可通过动画改变，用于有动画可能修改该对象的场景。[FACT] 默认用 Delete；只有在对象会被其他动画/系统修改时才用 Set。[FACT] 官方原话提示：Outfit 作者可预设这些 Shape Changers，让用户装衣服时自动配置好形态键；Reactive Object 系统响应其他 NDMF 兼容系统产生的动画，用户不一定要用 MA 的 toggle 系统也能获得这些形态键的收益。

教程 5 局限与创作者向：编辑器无法预览联动效果（用 Avatar 3.0 Emulator/Gesture Manager 测试）；服装作者可预设 Shape Changer 且 Reactive Object 响应 NDMF 动画

结论：教程 5 附带一个官方限制与一个创作者向建议。[FACT] 形态键联动效果在编辑器无法预览，官方建议用 Avatar 3.0 Emulator 或 Gesture Manager 在 Play 模式测试，且声明此限制在未来版本会改进。[FACT] 官方原话（创作者向）：‘Outfit authors can preset these Shape Changers, to allow for easy installation of clothing, with automatically configured blendshapes. The Reactive Object system responds to animations created by other NDMF-compatible systems, so your users don’t necessarily need to use Modular Avatar’s toggle system to get the benefits of these blendshapes.’[INFERENCE] 翻译要点：服装作者可预设 Shape Changer 使装机自动配置形态键；Reactive Object 系统响应 NDMF 兼容系统的动画，用户不一定依赖 MA toggle 系统；衣服作者应该预设这些以提升重用价值。

教程 6 手动构建 Animator（创作者向）：建层级→Bone Proxy 挂手→Animator Controller 双 Clip→Merge Animator 录制→MA Parameters(Internal)→菜单，官方原话 why would you?

结论：教程 6 教创作者用传统 Animator 方式实现手挂 Cube 开关 Prefab。[FACT] 官方 6 步：建 GameObject 层级（删 Cube 的 Box Collider 防影响手部追踪）→MA Bone Proxy 挂右手（Attachment Mode=‘As child; at root’）→建 Animator Controller（2 个 Clip、bool 参数 Cube、Transition Duration=0）→MA Merge Animator（勾 delete attached animator 与 match avatar write defaults）并额外加 Animator 组件仅供录制（build time 被删）→MA Parameters（Sync Mode=Bool、勾 Internal 防冲突）→Expressions Menu 资产 + MA Menu Installer。[FACT] 官方原话：‘You can also do this by building an animator manually, but why would you?’——说明这是给创作者的教程，教程 3 Object Toggle 是更快方式。[COMMUNITY] 易错点：参数冲突（没 Internal）、菜单不显示（MA Parameters 位置不对）、Cube 不出现（录制时没开 Cube）、WD 警告（没 match avatar write defaults）。

教程 6 三个关键组件约束：Internal 防同名参数冲突（默认推荐）、MA Parameters 须在 Merge Animator/Menu Installer 同对象或父级、Animator 组件仅为录制且 build time 删除

结论：教程 6 的组件配置有三个不可忽视的约束。[FACT] Internal 复选框：勾选后 MA 会确保同名参数不与 Avatar 上其他系统冲突（官方原文），默认推荐、99% 情况用它；关闭仅用于多个小组件需要共享参数时。[FACT] MA Parameters 位置：官方原文要求它在所有 Merge Animator 和 Menu Installer 的同一对象或父级，否则参数找不到。[FACT] Animator 组件（教程 6 额外加的）：官方原文说明加不加都无所谓，只是为了让 Unity 允许录制动画；勾 delete attached animator 后 MA 会在 build time 删除该组件。[FACT] Merge Animator 不要求位于顶层 GameObject，可放在层级更深位置。

教程 6 易错点：参数冲突/菜单不显示/Cube 不出现/WD 警告的排查（Internal、MA Parameters 位置、录制、match write defaults）

结论：教程 6 的四个易错点集中在参数与状态一致性。[FACT] ①参数冲突：没勾 Internal，勾上即可让 MA 避免同名参数干扰。[FACT] ②菜单没显示：MA Parameters 位置不对，移到 Merge Animator/Menu Installer 的同一对象或父级。[FACT] ③Cube 不出现：Animator 录制时没开 Cube，重录 CubeOn。[FACT] ④WD 警告：没勾 match avatar write defaults，或 Avatar 用 ON 而你用 OFF（或反之），勾上 match avatar write defaults 消除。

教程 6 与教程 3 对比：Object Toggle 新手友好且官方默认推荐（why would you?），手动 Animator 适合创作者处理复杂多状态机

结论：做对象开关优先 Object Toggle。[FACT] 对比：难度（教程 3 一星新手友好 vs 教程 6 三星需 Animator 基础）、步骤（5 步 vs 6 步、实际更繁琐）、受众（所有玩家 vs 创作者）、维护（加新开关=新建 GameObject vs 改 Animator+新增 Controller）、官方建议（默认用教程 3，官方对教程 6 的原话是 ‘why would you?’）。[INFERENCE] 教学要点：90% 玩家永远不应该学教程 6，但创作者必须理解——某些复杂场景（如复杂多状态机）必须用 Animator。
