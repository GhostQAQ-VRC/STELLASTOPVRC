常见导致 Avatar Very Poor 的五大原因：Skinned Mesh Renderer 过多居首，材质球、PhysBone 元件、面数、贴图依次排列

结论：常见导致 Very Poor 的原因是一组高发且易识别的问题模式，通常组合出现而非单一触发（community-tested，源页幽默化描述背后为实测常识）：

  1. Skinned Mesh Renderer 过多——最常见的 CPU 杀手。
  2. 材质球过多。
  3. PhysBone 元件过多。
  4. 面数过多。
  5. 贴图过大。

定位方法：这五项分别对应 PC/Quest 档位表中的 Skinned Mesh Renderer、Material Slots、PhysBone 元件数、面数、材质内存指标，排查顺序建议 SMR → 材质球 → PhysBone → 面数 → 贴图，对照档位表可快速锁定主因，再按最佳化优先级治理。

区分提示：这里的 Very Poor 是上传时 SDK 评估的档位结果，区别于玩家侧运行时限制导致的 Avatar 不可见。

Avatar 最佳化优先级八步（从易到难）：Light → 粒子 → 贴图内存 → 合并网格 → Atlas 化材质 → PhysBones → Bones → 面数

结论：提升 Avatar Performance Rank 的推荐操作顺序（从易到难，community-tested）：

  1. Light（光源）→ 能不要就不要。
  2. Particle System → 控制数量。
  3. Texture Memory → 降分辨率/压缩。
  4. Skinned Mesh → 合并。
  5. Material Slots → Atlas 化。
  6. PhysBones → 合并 + 精简。
  7. Bones → 合并。
  8. Polygons → Remove + Simplify。

验证方式：每完成一项后重新评估上传时的 Performance Rank，确认档位变化后再进入下一项。

路线逻辑：这是一条收益/成本递增路线——先处理成本低、效果明显的项（去光源、控粒子、压贴图），再做结构性合并（Skinned Mesh、材质球、PhysBones、Bones），最后才动面数；可与「常见导致 Very Poor 的原因」清单配合使用，完整实操细节在 optimization-guide。

SPS 规则：单个 SPS Socket 含 2 个 lights，Socket 存在即触发 Avatar 性能等级降为 Very Poor

结论：使用 SPS（Super Plug Shader，VRCFury 组件）会直接触发 Avatar 性能等级降为 Very Poor（FACT，来源 VRCFury 官方文档 vrcfury.com/sps/ 与 vrcfury.com/sps/constraints/）：单个 SPS Socket 包含 2 个 lights；即使 lights 被禁用也不影响渲染性能判定，但 Socket 本身的存在就会使 Avatar 变为 Very Poor。

触发条件：在 Avatar 上使用 VRCFury 的 SPS 组件并评估上传档位时。

原因：PC 平台光源 Poor 档预算仅 1 light，SPS 单 Socket 固定占 2 lights，直接超出预算；Quest 平台光源预算为 0 lights，严重超出。

优化策略：尽可能少用 Socket——每个 Socket 都会触发 Very Poor；不要用 Constraints 切换多个 Socket（抖动 + 性能损耗 + SPS 菜单功能失效）；充分利用 VRCFury 的 Point Light 自动管理机制。例外：无——Socket 存在即触发，靠禁用 light 无法规避。

SPS 与 PC/Quest 光源预算对比：PC Poor 档预算 1 light、Quest 为 0 lights，而 SPS 单 Socket 固定占 2 lights

结论：SPS 单 Socket 与平台光源预算的关系（FACT，来源 VRCFury 官方文档 vrcfury.com/sps/）：

平台 光源预算（Poor 档） SPS 单 Socket 占用 影响
PC 1 light 2 lights 直接触发 Very Poor
Quest 0 lights 2 lights 严重超出（Quest Very Poor 强制不显示）

单位说明：光源预算为 Performance Rank Poor 档阈值，单位是光源数量（light）；SPS = Super Plug Shader，VRCFury 组件。

设计推论：SPS 在 Quest 上不只是超档问题，还叠加「Very Poor 强制不显示」的平台行为，实际后果比 PC 更重；设计时应优先评估是否真的需要 SPS，并把「每 Socket 2 lights」计入平台光源预算，而不是假设禁用 light 就能规避。
