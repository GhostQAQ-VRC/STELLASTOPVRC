TexTransTool (TTT) — 非破坏性纹理改写工具（图集化/贴花/PSD 多层画布、Quest 适配与版本演进）

[FACT] TexTransTool (TTT) 可减少 Material 材质球数量，方式为 AtlasTexture 加 AllMaterialMergeReference。[FACT] TexTransTool

知识库 avatar

TTT 能压缩材质球与 VRAM，但不能直接减少材质槽数量

[FACT] TexTransTool (TTT) 可减少 Material 材质球数量，方式为 AtlasTexture 加 AllMaterialMergeReference。[FACT] TexTransTool (TTT) 可减少 Texture VRAM 占用，方式为 AtlasTexture 图集化。[FACT] TexTransTool (TTT) 不可直接减少 Material Slot 材质槽数量，必须配合 AvatarOptimizer (AAO) 的 MergeSkinnedMesh。[FACT] 官方文档（Tutorial/ReductionTextureMemoryByAtlasing）原文：AtlasTexture 的材质结合只是把材质合并到一起，不能合并材质槽；并强烈推荐与 Anatawa12/AvatarOptimizer 的 TraceAndOptimize 或 MergeSkinnedMesh 并用。[FACT] TexTransTool (TTT) 不做 Skinned Mesh 数量与 PhysBone 数量（由 AvatarOptimizer 处理），也不做 Mesh 面数（由 lilNDMFMeshSimplifier / Mantis 处理）。

TexTransTool 是 Unity Editor 内非破坏性纹理改写工具

[FACT] TexTransTool (TTT) 在 Unity Editor 内提供四类能力：1) 贴花（Decal）——直观的颜色/图案覆盖，可跨越 UV 边界；2) 图集化（Atlas）——智能合并多张纹理到一张，削减 VRAM；3) 专用纹理导入——非破坏地为 Avatar 应用纹理替换；4) PSD 导入与多层画布——在 Unity 内编辑 PSD 层级。[FACT] 与传统做法的区别：修改材质上，传统做法直接编辑 .mat 文件（破坏性），TexTransTool (TTT) 添加 NDMF 组件并在编译时改写；修改纹理上，传统做法是 Blender UV 重排加重导 PNG，TexTransTool (TTT) 在 Editor 内用 AtlasTexture 一键完成；回滚上，传统做法需要 Git/手动备份，TexTransTool (TTT) 禁用或删除组件即可；可叠加性上，传统做法为单次操作，TexTransTool (TTT) 为多组件链式组合。

TTT 安装：通过 VPM 仓库添加并在 VCC/ALCOM 启用包

[FACT] VPM 安装步骤：VCC/ALCOM 打开 Add Repo，粘贴 vcc://vpm/addRepo?url=https://vpm.rs64.net/vpm.json。[FACT] 添加仓库后在项目 Settings > Packages 中启用 TexTransTool 包。[FACT] TexTransCore 随 TexTransTool 自动安装，是 TexTransTool 的唯一硬依赖。[FACT] 若项目已有 Modular Avatar 或 AvatarOptimizer，NDMF 会自动安装。

TTT 依赖清单：必须 NDMF v1.7.0+ 与 TexTransCore v0.2.x+，TTCE-Wgpu 等可选

[FACT] 必须依赖一：NDMF v1.7.0+，Non-Destructive Modular Framework，随 Modular Avatar 自动安装。[FACT] 必须依赖二：TexTransCore v0.2.x+，TexTransTool 核心 C# 库（Generic 部分），随 TexTransTool 自动安装。[FACT] 可选依赖一：TTCE-Wgpu v0.2.0+，ComputeShader 后端（实验性），TexTransTool v0.10.7+ 可选启用。[FACT] 可选依赖二：ReinaS’ lilToon NDMF Utility，用于 lilToon 材质规范化，是 AtlasTexture BakeProperty 的替代品。[FACT] 可选依赖三：AvatarOptimizer，与 TexTransTool 强协作，用于减少 Material Slot。[FACT] 可选依赖四：Modular Avatar，与 TexTransTool 强协作，兼容运行。

TTT 仓库目录结构与依赖分层（TTT → TexTransCore → TTCE-Wgpu）

[FACT] TexTransTool 目录结构：Editor/ 为编辑器扩展（核心 UI）；Runtime/ 为运行时组件；MultiLayerImageData/ 为多层图像数据（PSD/Canvas 用）；ParserUtility/ 为解析器工具；TTCE-Unity/ 为 Texture Trans Core Engine 的 Unity 集成；TTT-PSDImporter/ 为 PSD 导入器；TestCode/ 为测试代码；DependentUpdater~/ 为依赖更新（VPM）；另有 CHANGELOG.md 与 CHANGELOG-EXPERIMENTAL.md（实验性功能变更）、LICENSE.md、package.json。[FACT] 依赖分层：TexTransTool (TTT) 以 TexTransCore 为唯一硬依赖，TexTransCore 可选依赖 TTCE-Wgpu（ComputeShader 后端）。

TTT 15 个核心组件清单与 Stable/Experimental 稳定性分级

[FACT] A 优化类（核心：图集化）：AtlasTexture 为 MainComponent + OwnedComponent，是图集化核心（VRAM 削减 + 材质合并）；TextureFineTuning 为 OwnedComponent，负责 AtlasTexture 的纹理压缩/格式配置。[FACT] B 改类（Decal 系）：SimpleDecal（简单贴花，跨 UV 边界）、SingleGradationDecal（单色渐变，专用头发等）、DistanceGradationDecal（距离渐变）、ParallelProjectionWithlilToonDecal（lilToon 并行投影）、MultiLayerImageCanvas（多层图像画布，Photoshop-like）。[FACT] C 纹理改写/混合类：TextureBlender（专用纹理导入，Stable v0.9.0）、ColorDifferenceChanger（颜色差异变换）、TextureConfigurator（OwnedComponent，纹理压缩/分辨率/MipMap）、MaterialModifier（材质修改）、NearTransTexture（近透明纹理）、MaterialOverrideTransfer（材质覆盖传输）。[FACT] D 选择器/工具类：IslandSelector（UV 岛选择器）、BoxIslandSelector、SphereIslandSelector、PinIslandSelector、IslandSelectorAND/OR/XOR/NOT（均 OwnedComponent，逻辑组合）、UVCopy（UV 复制）。[FACT] E 其他：TexTransToolPSDImporter（PSD 文件导入器）。[FACT] v1.0.0 稳定性：Stable 为 AtlasTexture / SimpleDecal / TextureBlender / SingleGradationDecal / IslandSelector 系；Experimental 为 DistanceGradationDecal / NearTransTexture / MultiLayerImageCanvas / ColorDifferenceChanger。[FACT] 判断方法：组件 Inspector 顶部显示「实验的」警告横幅。

AtlasTexture 两步核心算法：2D Bin Packing UV 重排 + UV 转写生成新纹理

[FACT] 核心定位：AtlasTexture 收集纹理中「需要的部分」重新排列到一张图集，减少 VRAM 占用。[FACT] 第一步 UV 再配置：2D Bin Packing 把每个材质的 UV island 重新排列到一张大纹理上。[FACT] 第二步 UV 转写：按新的 UV 重新生成纹理内容，早期用重心坐标系，现已改为矩形转写。[FACT] 性能：v0.1.x 时单个图集化需约 2 分半，现在秒级完成（GPU 加速）。[FACT] 历史：AtlasTexture 在 TTT v0.0.0 时期即存在，是 TTT 最早的核心组件，最初叫 AtlasSet，工具名也叫 TexturAtlasCompiler。[COMMUNITY] 设计灵感：AvatarOptimizer (AAO) 的非破坏性 Mesh 合并，对应 TexTransTool (TTT) 的非破坏性 Texture 合并。

AtlasTexture 前置条件与 Shader 支持矩阵（lilToon 完全支持）

[FACT] Renderer 前置条件：编译时 Active（或勾选「適用時に非アクティブなレンダラーを含める」）；tag 不等于 EditorOnly；有 Mesh + UV0；有 1 个以上材质。[FACT] lilToon 完全支持，包括 MatCap、Shadow、3rd、NormalMap、HSVG 等所有变体。[FACT] Standard 支持；VRCSDK StandardLite 支持；VRCSDK ToonLit 支持。[FACT] 其它 Shader 默认按 _MainTex 走 UV0，可在 ITTShaderTextureUsageInformation 扩展。

AtlasTexture 完整配置项：Material Selector 到 Pixel Normalize

[FACT] Material Selector（マテリアルセレクター）：Material 列表，勾选要图集化的材质，未勾选的不参与；Refresh Materials 为刷新材质列表按钮。[FACT] Island Size Priority（アイランド大きさ優先度）：结构，调整 Island 大小优先级，可通过 Set From Material 按材质分配、Set From Island Selector 按 Island Selector 分配。[FACT] Material Merge Group（マテリアル結合グループ）：分组合并材质，每组内的材质合并到指定 Reference。[FACT] All Material Merge Reference（すべてのマテリアル結合時参照）：全材质合并目标，是 Quest 适配关键。[FACT] Atlas Texture Size（アトラステクスチャーサイズ）：2 的幂的输出纹理大小，默认正方形；Custom Aspect 启用自定义宽高比，Atlas Texture Height 为高度上限。[FACT] Atlas Target UV Channel：enum，可选 UV0 / UV1 / UV2 / UV3。[FACT] Padding（パディング）：Island 间隔（UV 尺度）。[FACT] Include Disable Renderer（適用時に非アクティブなレンダラーを含める）：bool，包含非活跃 Renderer。[FACT] Force Size Priority（大きさの優先度を強制）：bool，不因空间不足而强制按优先级缩放。[FACT] Force Set Texture（テクスチャーを強制的にセットする）：bool，无纹理也强制覆盖材质纹理。[FACT] Background Color：Color，Atlas 背景色，影响 mipmap 和压缩。[FACT] Pixel Normalize（ピクセルノーマライズ）：bool，像素对齐，避免纹理劣化。

AtlasTexture 标准工作流：创建 → 勾选材质 → 分组 → 设合并目标 → 调尺寸 → 烘焙/上传

[FACT] 步骤 1：Avatar 根节点右键 → Create → TexTransTool/TTT AtlasTexture，自动在 Avatar 内创建 GameObject「AtlasTexture」并列出所有材质。[FACT] 步骤 2：Material Selector 勾选要合并的材质。[FACT] 步骤 3：按性质分组（如皮肤/头发/衣服/半透明/金属），不同性质的材质不能合在一组（透明混合会出错）。[FACT] 步骤 4：设定合并目标 All Material Merge Reference，可选把所有材质合并到一个 Quest 材质。[FACT] 步骤 5：调整 Atlas Texture Size，一般 2048 或 4096。[FACT] 步骤 6：运行 Manual Bake Avatar 或 Play 模式触发，NDMF Console 应显示无错并显示 Atlas 再配置结果。[FACT] 步骤 7：验证，跟随 Renderer 的 Material 查看新纹理。[FACT] 步骤 8：上传时自动应用。

AtlasTexture 设计原则：必须按材质性质分组，材质合并不等于材质槽合并

[FACT] 必须按材质性质分组（皮肤/头发/衣服/半透明/玻璃/金属），否则透明材质会混合错误。[COMMUNITY] 复杂材质合并出问题时的处理：备份材质 → 选合适烘焙选项 → 完成（烘焙尝试）。[FACT] 材质合并不是材质槽合并：合并材质指减少 Material 文件数，用 Merge Reference 实现；合并材质槽必须用 AvatarOptimizer MergeSkinnedMesh。[FACT] 另见能力边界：AllMaterialMergeReference 把所有材质合并到 Quest 材质，仍不合并材质槽。

Quest 适配：All Material Merge Reference + Force Set Texture 让 Quest 端只剩 1 个材质与 1 张图集

[FACT] AtlasTexture 级设置：Material Selector 勾选 All Materials（全部勾选）；All Material Merge Reference 拖入 Quest 专用 Shader 的材质；Force Set Texture 设 True；Atlas Texture Size 设 2048 或 4096（视模型复杂度）；Material Merge Group 留空（用 All Material Merge Reference 替代）。[FACT] 原理：PC 端保留原材质细节，Quest 端强制替换为 Quest Material（Mobile 优化简单 Shader，推荐 lilToon）。[FACT] 效果：Quest 端所有 Renderer 用同一材质（节省 Material Slot 调用），所有纹理合并到 1 张（节省 VRAM × N）。[FACT] AAO 协作三步：1) TexTransTool (TTT) 处理所有纹理合并 + Quest Material 替换；2) AvatarOptimizer (AAO) 用 MergeSkinnedMesh 合并 Skinned Mesh（Material Slot 真正减少）；3) 最终 Material Slot 极少 + VRAM 极小 + 性能 Excellent。

SimpleDecal：Unity 内直观贴花、可跨 UV 边界，支持 Material Filtering 与 Island Selector

[FACT] 核心优势：传统贴花需要 UV 编辑软件且可能跨越 UV 边界失败；TexTransTool (TTT) SimpleDecal 在 Unity 内操作、直观、可跨越 UV 边界。[FACT] Material Filtering：只对特定材质生效。[FACT] Island Selector：用 UV Island 级别限制贴花范围。[FACT] Back Culling：背面剔除，v0.9.0 改名前叫 SideCulling。[FACT] Auto / Manual Select：v0.9.0 新增 Auto 自动选择模式。[FACT] Color Multiply：v0.3.0 起支持贴花颜色调整。[FACT] 性能演进：v0.1.x 单个贴花需 5 秒（CPU 实现）；v0.9.0 ComputeShader 实现，秒级；v0.10.x 回归高质量 Padding（v0.2.x 风格）。

SimpleDecal 标准工作流：创建 → 设贴花纹理 → Gizmo 调整 → 可选过滤 → 烘焙/上传

[FACT] 步骤 1：Avatar 根节点右键 → Create → TexTransTool/TTT SimpleDecal。[FACT] 步骤 2：设置 Decal Texture（贴花纹理）。[FACT] 步骤 3：调整位置/角度（Gizmo 直观操作）。[FACT] 步骤 4：调整 Scale / MaxDistance。[FACT] 步骤 5（可选）：启用 Material Filtering 限制范围。[FACT] 步骤 6（可选）：启用 Island Selector 进一步限制。[FACT] 步骤 7：Manual Bake / Play / Upload。

MultiLayerImageCanvas：Unity 内免 Photoshop 编辑 PSD 多层纹理（实验性）

[FACT] MultiLayerImageCanvas 是画布主组件，用于在 Unity Editor 内直接编辑 PSD 多层图像，无需 Photoshop。[FACT] 关联组件：LayerFolder（文件夹层）、RasterLayer（光栅图层）、SolidLayer（单色图层）、TexTransToolPSDImporter（PSD 导入器，右键 Asset 即可使用）。[FACT] 使用场景一：在 Unity 内直接编辑 Avatar 纹理的图层（添加新元素、修改颜色）。[FACT] 使用场景二：PSD 文件作为 Avatar 纹理源的导入。[FACT] 状态：该功能为 Experimental（实验性）。

TTT 与 AAO 的 NDMF 深度集成：RemoveMeshBy 区域感知与 UV 通道共享

[FACT] 集成 1（RemoveMeshBy* 与 AtlasTexture 协作）：AvatarOptimizer 的 RemoveMeshByBlendShape 删除某些面，但 AtlasTexture 若不知道仍会为这些面预留图集空间造成浪费；AtlasTexture 通过 AvatarOptimizer 的 API 知晓哪些区域将被删除，不为这些区域分配图集空间，从而节省图集面积。[FACT] 集成 2（UV 通道共享）：AvatarOptimizer 把原 UV 写入 Mesh UV1，AtlasTexture 改 UV0 会破坏 AvatarOptimizer 的引用；AtlasTexture 通过 AvatarOptimizer 的 API 报告 UV 改写位置，AvatarOptimizer 可正确同步。

推荐 NDMF 执行顺序：MA 先行 → TTT Decal/Atlas 次之 → AAO MergeSkinnedMesh → TraceAndOptimize

[FACT] 推荐 NDMF 执行顺序：1) Modular Avatar + 其他 NDMF 工具（增加/修改内容类）；2) AtlasTexture / SimpleDecal / Decal 系（TexTransTool (TTT)）；3) AvatarOptimizer.MergeSkinnedMesh（合并 Mesh + Material Slot）；4) AvatarOptimizer.TraceAndOptimize（最终优化）。[FACT] Mantis LOD Editor 协作：v0.8.11 起修复，TexTransTool (TTT) 必须在 Mantis LOD Editor 之后执行（因为 Mantis 可能减面）。

故障排查：TTT 组件不生效、Gizmo 不显示、图标碍事的修复方法

[FACT] 问题 1（上传/Play/Manual Bake 不生效）原因与修复：组件未 Active → 激活组件；NDMF 未安装 → 安装 NDMF（v1.7.0+）；预发布版本不匹配 → 同时更新 NDMF 到预发布版。[FACT] 问题 2（Gizmo 不显示）原因 1：SceneView 右上角 Gizmo 总开关关闭 → 点击启用（图标变蓝）；原因 2：组件单独 Gizmo 开关关闭 → 在 Gizmo 总开关右边的下拉菜单中重新启用。[FACT] 问题 3（图标碍事）：Gizmo 总开关下拉 → 调小 3D Icons 或单独禁用；高级方案：用作者提供的脚本（gist）批量禁用。

GTX10/9XX 与 AMD Radeon 在 DirectX11 下 TTT 故障：升级 v0.10.0+ 或改用 Vulkan；VMware 无解

[FACT] 已知问题 GPU：GTX 1080 / 1070 TI / 1070 / 1060 与 GTX 980。[FACT] 影响组件：SimpleDecal / SingleGradationDecal（v0.9.x 必坏）、TexTransTool PSD Importer。[FACT] 修复：升级到 v0.10.0（已修复）；临时方案：UnityEditor 用 Vulkan 启动，操作路径为 ALCOM → 项目管理 → 修改启动选项 → 定制命令行参数 → 添加 -force-vulkan → 保存。[FACT] AMD Radeon + DirectX11 故障：影响 TTT PSD Importer（v0.9.x ~ v0.10.x），修复为使用 Vulkan（方法同上）。[FACT] VMware 故障：确认环境 VMware Workstation 17 Pro 17.6.2 build-24409262 下 ComputeShader 实现与 VMware 不兼容，连最基础的 NotBlend Blending 都失败，无解，需换用其他环境。

旧版 TTT 资产与新版本不兼容：用 Tools > TexTransTool > Migrator 迁移

[FACT] 问题 7（TTT 资产不工作）原因：资产由旧版本 TexTransTool (TTT) 创建；修复：1) 备份 Prefab；2) Tools > TexTransTool > Migrator 打开；3) 运行迁移。[FACT] 问题 8（旧资产升级到 v0.8.x+ 后报错）：v0.8.x 移除了 ReferenceResolver，v0.9.x 移除了 TexTransListGroup；必须通过 Migrator 窗口执行迁移。

TexTransCore 是 TTT 唯一硬依赖，TTCE-Wgpu 是可选 ComputeShader 后端

[FACT] TexTransCore 是 TexTransTool (TTT) 唯一的硬依赖，托管在 github.com/ReinaS-64892/TexTransCore。[FACT] TexTransCore 的作用：TexTransTool (TTT) 的 C# Generic 部分（与 Unity 解耦），因版本管理需要分离。[FACT] 必要性：无 TexTransCore 则 TexTransTool (TTT) 无法运行。[FACT] 管理：TexTransCore 随 TexTransTool (TTT) 自动安装，无需手动操作。[FACT] TTCE-Wgpu 的作用：TexTransTool (TTT) 的 ComputeShader 后端（实验性）。[FACT] TTCE-Wgpu 必要性：可选；何时使用：解决特定 GPU 兼容性 / 性能优化。

TTT 版本演进：v0.1.0 初版（2023-06-02）到 v1.0.0 稳定版（2025-06-22）与 v1.0.1

[FACT] v0.1.0（2023-06-02）：初次发布，包含 SimpleDecal + TextureBlender + AtlasSet。[FACT] v0.3.0（2023-09-04）：AtlasTexture 加入，取代 AtlasSet。[FACT] v0.4.0（2023-10-07）：NDMF 官方支持。[FACT] v0.9.0（2025-02-17）：NDMF Preview + AvatarOptimizer RemoveMeshBy* 协作 + ComputeShader 实现。[FACT] v0.10.0（2025-05-14）：大改动——Marge→Merge、BakeProperty 删除、TexTransGroup 删除、DirectX11 + GTX10 修复。[FACT] v1.0.0（2025-06-22）：稳定版——清理旧数据、ProjectMigrationDialog 删除。[FACT] v1.0.1（2025-12-26）：iOS 构建修复。

TTT v0.10.0 破坏性变更清单：重命名 MargeMaterial → AllMaterialMergeReference，删除 TexTransGroup 等

TTT 设计哲学：让 Avatar 制作者摆脱 UV 拼图，v1.0.0 后不再有大改版
