VRChat Constraints 约束系统：让 Avatar/World 的 Transform 相对其他 Transform 移动、旋转、缩放

结论：VRChat 提供自定义约束系统（VRChat Constraints），允许 Avatar 或 World 中的 Transform 相对于其他 Transform 进行移动、旋转和缩放，典型用途是让一个物体跟随另一个物体运动，例如配饰跟随角色骨骼（来源：creators.vrchat.com/common-components/constraints/，official，Avatar 需 SDK 3.7.0+、World 需 SDK 3.10.0+）。

命名空间：约束组件位于 VRC.SDK3.Dynamics.Constraint.Components 与 VRC.Dynamics 两个命名空间，编写脚本或在工程中检索约束组件时应在这两处查找。

版本可用范围：

  • Avatar 场景：自 SDK 3.7.0 起可直接使用 VRChat Constraints。
  • World 场景：自 SDK 3.10.0（2025-10-24）起获得约束支持，约束由此从 Avatar 专用扩展为通用能力。

合规要点：Avatar 中若存在 Unity 原生 Constraints，上传时会被自动转换为 VRChat Constraints——Avatar 场景 VRChat Constraints 是唯一合规方案。

Avatar 必须使用 VRChat Constraints：含 Unity Constraints 时上传自动转换，性能更好且功能更多

结论：Avatar 必须使用 VRChat Constraints；如果 Avatar 中包含 Unity 原生 Constraints，上传时会由 SDK 自动转换为 VRChat Constraints（来源：creators.vrchat.com/common-components/constraints/，official，SDK 3.7.0+ 口径）。

两者差异对照：

  • 适用对象：Avatar 推荐（实质强制）使用 VRChat Constraints；Unity Constraints 在 Avatar 上不能保留原样，仅靠上传自动转换兜底。World 场景两类均可使用。
  • 性能：VRChat Constraints 性能更好；Unity Constraints 可能产生性能问题。
  • 功能：VRChat Constraints 提供更多可选功能；Unity Constraints 仅提供基础功能。

实践含义：新建或改造 Avatar 时应直接摆放 VRChat Constraints 组件，而不是放置 Unity Constraints 后依赖上传时的自动转换。

VRChat Constraints 版本时序：3.6.2-constraints open-beta 起步、SDK 3.7.0 正式发布（2024-08-16）、3.10.0 扩展到 World

结论：VRChat Constraints 按「开放测试 → 正式发布 → 扩展到 World」三阶段演进：SDK 3.6.2-constraints.1～4 为 open-beta，SDK 3.7.0 于 2024-08-16 正式 live 发布并脱离 beta，SDK 3.10.0（2025-10-24）扩展到 World（来源：github.com/vrchat/packages/releases 官方 release 历史，official，覆盖 SDK 3.6.2-constraints.1 ～ 3.10.0）。

时间线明细：

  • SDK 3.6.2-constraints.1 至 3.6.2-constraints.4：open-beta 测试阶段，官方说明均为 “This is an open-beta release for VRChat Constraints.”。
  • SDK 3.7.0-beta.1 / beta.2：3.7.0 正式版前的 open-beta 周期。
  • SDK 3.7.0（2024-08-16）：正式 live release，官方说明 “This is a live release!”，VRChat Constraints 自此脱离 beta；同一版本还修复了同时选中多个 VRChat Constraint 并编辑其 sources 列表时约束源丢失引用的问题。
  • SDK 3.10.0（2025-10-24）：从 Avatar 扩展到 World，成为通用约束能力。

各 SDK 版本下 Avatar 约束可用方案：3.7.0 前仅 Unity 加自动转换、3.7.0 起直用 VRC Constraints、3.10.0 起 World 可用

结论：Avatar 能否直接使用 VRChat Constraints 由工程实际的 VRChat SDK 版本决定，分三个阶段判断（来源：github.com/vrchat/packages/releases + creators.vrchat.com/common-components/constraints/，official，SDK 3.6.2 ～ 3.10.0）：

  • SDK 3.7.0 之前：Avatar 只能使用 Unity Constraints，由 SDK 在上传时自动转换为 VRChat Constraints。
  • SDK 3.7.0 起（2024-08-16 正式发布）：创作者可直接使用 VRChat Constraints，不再依赖自动转换，功能更可控。
  • SDK 3.10.0 起（2025-10-24）：VRChat Constraints 从仅 Avatar 可用扩展为 Avatar 与 World 通用。

工程决策用法：SDK 低于 3.7.0 只能走 Unity Constraints 加上传自动转换路径；达到 3.7.0 及以上应直接采用 VRChat Constraints。排查旧 Avatar 工程时看到的 Unity Constraints，通常就是历史上传自动转换路线的痕迹。

VRCAimConstraint 目标约束用法与五类参数：Is Active、Weight、Aim Vector、Up Vector、World Up Type 五种取值

结论：VRCAimConstraint（目标约束）用于旋转目标 Transform 使其朝向源，并可通过 Aim Vector 自定义前进方向、通过 Up Vector 与 World Up Type 控制向上参考（来源：creators.vrchat.com/common-components/constraints/，official，Avatar 需 SDK 3.7.0+、World 需 SDK 3.10.0+）。

参数一览：

  • Is Active：控制约束是否评估，即是否参与计算。
  • Weight：整体权重，取值范围 0 到 1。
  • Aim Vector：控制以哪个轴指向源。
  • Up Vector：控制向上的轴。
  • World Up Type：世界向上参考类型，共五种取值——Scene Up（场景 Y 轴）、Object Up（指定对象的向上方向）、Object Up Rotation（局部空间）、Vector（世界空间向量）、None（无）。

组合用法：调整朝向行为时，Aim Vector 决定哪个轴对准源，Up Vector 与 World Up Type 决定计算朝向时的向上参考基准，两者配合确定最终姿态。

VRC Constraints 解决的问题与适用范围：位移/旋转/缩放的规则化绑定，道具挂手、饰品跟随头部等场景

结论：VRChat Constraints（简称 VRC Constraints，常称「VRC 约束/约束系统」）是 VRChat 官方提供的自定义约束系统，允许 Avatar 或 World 中的某个 Transform 相对于其他 Transform 进行移动、旋转和缩放（来源：creators.vrchat.com/common-components/constraints/，official，知识库页 v1.1 复核于 2026-07-04）。

解决的问题：把物体 A 的位移/旋转/缩放按规则绑定到物体 B 上形成相对运动，典型场景如道具挂在手上、饰品跟随头部、部件持续朝向目标。

适用范围：Avatar（角色模型）与 World（世界/场景）两类场景均可用约束建立 Transform 之间的相对运动关系。

关联事实：对 Avatar 必须使用 VRC Constraints（含 Unity Constraints 时上传自动转换）；自 SDK 3.10.0（2025-10-24）起从 Avatar 扩展到 World 成为通用方案；相关命名空间为 VRC.SDK3.Dynamics.Constraint.Components 与 VRC.Dynamics。

Avatar 约束必须用 VRChat Constraints 的两条实践含义：误用不报错但转换不可控，World 场景不受限

结论：为 VRChat Avatar 配置约束时必须使用 VRChat Constraints 组件；放置的是 Unity 原生 Constraints 时上传会被 SDK 自动转换，但转换过程不受创作者控制（来源：creators.vrchat.com/common-components/constraints/，official，以 SDK 3.7.0（2024-08-16）前后行为分界）。

实践含义两点：

  1. 误用 Unity Constraints 不会导致上传失败——最终上传产物会被统一转换。
  2. 转换过程不受创作者控制，为保证行为与功能符合预期，应直接使用 VRC Constraints 组件。

边界：此强制要求仅针对 Avatar；World 中 Unity Constraints 与 VRC Constraints 都可使用，不做强制转换。

版本背景：SDK 3.7.0 之前创作者实际只能编写 Unity Constraints 并依赖上传自动转换获得 VRC Constraints；自 3.7.0 起可在工程中直接使用 VRC Constraints，无需再依赖自动转换。

多选多个 VRChat Constraints 同时编辑源列表会丢失约束源引用：SDK 3.7.0 已修复的历史缺陷

结论：「多选多个 VRChat Constraints 后同时编辑其 sources 列表会导致约束源引用丢失」是已被官方修复的历史缺陷，修复版本为 SDK 3.7.0（2024-08-16 正式发布）（来源：github.com/vrchat/packages/releases 官方 release 说明，official，缺陷存在于 3.7.0 之前版本）。

VRCAimConstraint 的 Constraint Settings 四项：Rotation At Rest 基准姿态、Rotation Offset 微调、Lock 锁定、Freeze Rotation Axes 冻结轴

结论：VRCAimConstraint（瞄准约束）的 Constraint Settings 区域包含 4 个设置项——Rotation At Rest、Rotation Offset、Lock、Freeze Rotation Axes（来源：VRChat 官方文档《VRC Constraints》参考页 §2.1，official）。

逐项含义：

  • Rotation At Rest：权重为 0 时目标 Transform 所呈现的旋转，是约束不生效时的基准姿态。
  • Rotation Offset：叠加在约束结果上的旋转偏移，用于在不改动源的情况下微调最终朝向。
  • Lock：将 At Rest 与 Offset 一并锁定，防止误修改。
  • Freeze Rotation Axes：冻结特定的轴，被冻结的轴不参与约束驱动。

配置入口：VRCAimConstraint 组件 Inspector 的 Constraint Settings 折叠区；四项与基础参数（Is Active/Weight/Aim Vector/Up Vector/World Up Type）共同构成该组件的完整参数面板。

VRCAimConstraint 目标约束总览：旋转朝向源、Aim Vector 定前进轴、World Up Type 五模式（Scene Up/Object Up/Object Up Rotation/Vector/None）

结论：VRCAimConstraint（目标约束）通过旋转目标 Transform 使其朝向源（Source），并支持自定义用作「前进方向」的轴；最终姿态由「Aim Vector 决定哪个轴指向源」与「Up Vector 决定向上轴」共同确定（来源：creators.vrchat.com/common-components/constraints/，official，SDK 3.7.0+ 现状）。

适用场景：需要让部件持续指向另一物体时使用，例如眼睛注视点、指示器/天线指向目标、指针类部件。

参数清单：

  • Is Active——控制该约束是否参与评估。
  • Weight——整体权重，取值 0 到 1。
  • Aim Vector——控制朝向源的轴（即前进方向）。
  • Up Vector——控制向上轴。
  • World Up Type——世界向上参考的类型，共五种：Scene Up（场景 Y 轴）、Object Up（指定对象的向上方向）、Object Up Rotation（局部空间）、Vector（世界空间向量）、None（无）。

仅需正 Z 轴朝向、不需要方向定制时可改用简化版 VRCLookAtConstraint。

VRCLookAtConstraint 注视约束：正 Z 轴朝向源的简化版 Aim，Use Up Object 与 Roll 二选一控制翻滚

结论：VRCLookAtConstraint（注视约束）是简化版的 Aim Constraint，作用是让目标 Transform 的正 Z 轴朝向源对象，适合实现物体持续看向某一目标的注视效果（来源：VRChat 官方文档《VRC Constraints》参考页 §2.2，official）。

参数说明：

  • Is Active：控制该约束是否参与评估。
  • Weight：整体权重，取值范围 0 到 1。
  • Use Up Object：是否使用单独的对象来控制翻滚。
  • Roll：在没有使用 Up Object 时，直接以角度值控制绕 Z 轴的翻滚。
  • World Up Object：用作翻滚参照的目标对象。

翻滚控制二选一：不使用 Up Object 时以 Roll 数值控制绕 Z 轴角度；启用 Use Up Object 后由指定对象决定翻滚。

使用要点：只需要基本朝向功能保持默认即可；需要精确控制上方向翻滚时，再在 Roll 数值与指定 Up Object 两种方式中选择其一。

VRCParentConstraint 父约束：像子对象一样移动旋转跟随但不改层级，每个源的偏移独立设置

结论：VRCParentConstraint（父约束）会同时移动和旋转目标 Transform，使其表现如同目标是源的子对象，但无需真的把目标挂到源下面改变层级（来源：VRChat 官方文档《VRC Constraints》参考页 §2.3，official）。

公共参数：Is Active 控制该约束是否参与评估；Weight 为整体权重，取值 0 到 1。

Constraint Settings：

  • Position/Rotation At Rest：静止位置/旋转，权重为 0 时的基准。
  • Position/Rotation Offset：位置/旋转偏移量。
  • Lock：锁定这些设置。
  • Freeze Position/Rotation Axes：冻结指定轴，被冻结的轴不受影响。

重要细节——每个源的偏移是独立设置的：存在多个源时，每个源各自保有自己的 At Rest 与 Offset 组合，而不是所有源共用一组数值，需分别配置。

VRCPositionConstraint 位置约束：只匹配源的位置不影响旋转缩放，At Rest 基准加 Offset 偏移加单轴冻结

结论：VRCPositionConstraint（位置约束）只改变目标 Transform 的位置，使其匹配源的位置，不影响目标的旋转与缩放（来源：VRChat 官方文档《VRC Constraints》参考页 §2.4，official）。

参数说明：Is Active 控制该约束是否参与评估；Weight 为整体权重，取值范围 0 到 1。

Constraint Settings：

  • Position At Rest：静止位置，即权重为 0 时目标的基准位置。
  • Position Offset：在匹配结果上叠加的位置偏移。
  • Lock：锁定上述设置。
  • Freeze Position Axes：冻结指定的位置轴，被冻结的轴不再跟随源移动（仍保持原值）。

典型用途：让附件、道具等对象的位置持续跟随另一个对象，例如手持物对齐手部骨骼。

VRCRotationConstraint 旋转约束：只匹配源的旋转不影响位置缩放，披风末端对齐身体转动类场景

结论：VRCRotationConstraint（旋转约束）只改变目标 Transform 的旋转，使其匹配源的旋转，不影响目标的位置与缩放（来源：VRChat 官方文档《VRC Constraints》参考页 §2.5，official）。

参数说明：Is Active 控制该约束是否参与评估；Weight 为整体权重，取值范围 0 到 1。

Constraint Settings：

  • Rotation At Rest：静止旋转，即权重为 0 时目标的基准旋转。
  • Rotation Offset：叠加在匹配结果上的旋转偏移。
  • Lock：锁定上述设置。
  • Freeze Rotation Axes：冻结指定的旋转轴，被冻结的轴不再跟随源旋转（仍保持原值）。

典型用途：让附件、装饰物的朝向持续跟随另一对象，例如披风末端对齐身体某部位的转动。

VRCScaleConstraint 缩放约束：只匹配源的缩放，Scale At Rest 基准、Scale Offset 偏移、Freeze Scale Axes 单轴冻结

结论：VRCScaleConstraint（缩放约束）只改变目标 Transform 的缩放，使其匹配源的缩放，不影响目标的位置与旋转（来源：VRChat 官方文档《VRC Constraints》参考页 §2.6，official）。

参数说明：Is Active 控制该约束是否参与评估；Weight 为整体权重，取值范围 0 到 1。

Constraint Settings：

  • Scale At Rest：静止缩放，即权重为 0 时目标的基准缩放。
  • Scale Offset：叠加在匹配结果上的缩放偏移。
  • Lock：锁定上述设置。
  • Freeze Scale Axes：冻结指定的缩放轴，被冻结的轴不再跟随源变化（仍保持原值）。

典型用途：让道具、特效对象的大小随源对象同步放大缩小，保持视觉比例一致，例如变身、联动道具场景。

VRC Constraints 公共参数模式：Is Active 总开关加 Weight 整体权重 0-1，五种约束组件统一开头

结论：VRChat 的 VRC Constraints 组件族共享统一的基础参数模式——Is Active（约束是否参与评估的总开关）与 Weight（整体权重，0 到 1，调节约束影响强弱）；掌握一组即可举一反三用到所有约束组件（来源：VRChat 官方文档《VRC Constraints》参考页 §2.2–§2.6 参数列表归纳，official）。

两项公共参数：

  • Is Active：控制该约束组件是否参与评估，相当于约束的总开关。
  • Weight：整体权重，取值范围 0 到 1，用于调节约束影响的强弱程度。

覆盖证据：官方参考页中 VRCLookAtConstraint、VRCParentConstraint、VRCPositionConstraint、VRCRotationConstraint、VRCScaleConstraint 五个组件的参数列表均以这两项开头，其后才是各自专属的 Constraint Settings（At Rest、Offset、Lock、Freeze Axes 等）。

Target Transform 高级设置：约束可驱动附加对象以外的目标，但不能通过动画更改

结论：VRC Constraints 组件提供高级设置 Target Transform，用于更改约束实际驱动的目标 Transform；字段为空时约束应用于组件所附加的那个 Transform 本身，填入其他对象即可让约束去移动或旋转附加对象之外的目标（来源：VRChat 官方文档《VRC Constraints》参考页 §3 高级设置，official）。

默认行为：Target Transform 为空 → 约束作用于自身附加的 Transform。

扩展用法：将其他对象填入 Target Transform → 约束改为驱动该目标，可把约束组件集中挂在一个物体上而去驱动场景中的其他物体。

硬性限制：Target Transform 不能通过动画更改——无法在运行过程中用 Animation 切换约束的作用对象；作用目标需要在构建期（编辑时）确定下来。

Solve In Local Space 开关：关=世界空间求解贴住源、开=局部空间求解随骨骼链，假肢体场景开

结论：Solve In Local Space 决定 VRC Constraints 求解所处的空间——关闭时在世界空间求解，目标匹配源的世界位置/旋转/缩放；开启时在局部空间求解，目标匹配源的局部位置/旋转/缩放（来源：VRChat 官方文档《VRC Constraints》参考页 §3 高级设置，official）。

两种模式对照：

  • 关闭（世界空间求解）：无论源处于层级中的哪个位置，目标都在世界坐标下贴合源。
  • 开启（局部空间求解）：保持的是目标与源之间的局部相对关系。

典型用途：假肢体（fake limbs）、跟随骨骼链等场景适合开启局部空间求解——这类效果关心的是相对父级的局部关系而非世界坐标对齐，结果会随整条骨骼链一起运动。

选择方法：要让目标在世界坐标里贴住源就关闭；要让目标作为源局部坐标系中的一员跟随运动就开启。

Freeze To World 世界冻结：忽略所有源锁定世界空间、必须冻结全部轴才完全停止、区别于禁用约束组件

结论：Freeze To World 是 VRC Constraints 的高级设置——启用后约束忽略所有源，主动把目标 Transform 锁定在世界空间中，典型用途是「把物体放进世界」，例如放下一个道具后让它停在原地不跟随 Avatar 移动（来源：VRChat 官方文档《VRC Constraints》参考页 §3 高级设置，official）。

关键要点一（必须全轴冻结）：必须冻结所有轴物体才会完全停止；若只冻结部分轴，其余轴仍会被约束驱动继续运动。开启后物体还在动时，先检查是否所有轴都已冻结。

关键要点二（与禁用约束的区别）：禁用约束组件时 Transform 只是在局部空间停止被驱动，但仍跟随父对象一起移动；Freeze To World 则主动移动 Transform 来抵消父级运动，确保物体在世界空间中保持不动。

结论性选择：想让物体脱离 Avatar 固定于世界时，用 Freeze To World 而不是简单地关闭约束。

Rebake Offsets When Unfrozen 解冻重烘焙：解冻瞬间重算相对源的偏移而非沿用原始偏移

结论：Rebake Offsets When Unfrozen 控制 VRC Constraints 在解冻时刻如何处理偏移——启用时解冻瞬间重新计算目标相对于源的偏移（承认当前位姿并据此生成新的 Offset），关闭时保持原始偏移不变、解冻后回到按原 Offset 计算出的位姿（来源：VRChat 官方文档《VRC Constraints》参考页 §3 高级设置，official）。

配合关系：它与 Freeze To World 同属冻结相关的高级设置；当物体在冻结期间发生了位移（例如被放到世界中的新位置），是否把这个新位置作为解冻后的跟随基准，正是由此开关决定。

决策口径：冻结期间目标与源的相对关系发生了变化、希望解冻后以当前相对关系继续时启用；希望解冻后恢复冻结前的原始相对姿态时关闭。

六种约束类型总览与选用思路：Aim/LookAt 管朝向、Parent 管整体跟随、Position/Rotation/Scale 管单属性

结论：VRChat Constraints 共提供六种约束组件，覆盖 Transform 的朝向与位移、旋转、缩放跟随需求；选用思路是朝向选 Aim 或更简单的 LookAt、整体跟随选 Parent、单一属性在 Position/Rotation/Scale 中按需选择（来源：creators.vrchat.com/common-components/constraints/ §2 约束类型，official，SDK 3.7.0+）。

六种组件清单：

  1. VRCAimConstraint（目标约束）：旋转目标 Transform 使其朝向源，可自定义前进方向。
  2. VRCLookAtConstraint（注视约束）：简化版 Aim Constraint，使目标正 Z 轴朝向源。
  3. VRCParentConstraint（父约束）：移动并旋转目标，效果如同目标是源的子对象。
  4. VRCPositionConstraint（位置约束）：改变目标位置以匹配源位置。
  5. VRCRotationConstraint（旋转约束）：改变目标旋转以匹配源旋转。
  6. VRCScaleConstraint（缩放约束）：改变目标缩放以匹配源缩放。

选用速查：只需朝向 → Aim 或 LookAt；像子对象一样整体跟随（位置加旋转）→ Parent；只跟单一属性 → Position / Rotation / Scale 三选一。

VRCAimConstraint 全参数面板：基础五参数加 Constraint Settings 四项（At Rest/Offset/Lock/Freeze Rotation Axes）

结论：VRCAimConstraint（目标约束）旋转目标 Transform 使其朝向源并可自定义前进方向，适合让武器、视线、指示物持续指向目标的场景；参数由基础参数组与 Constraint Settings 组构成（来源：creators.vrchat.com/common-components/constraints/ §2.1，official，SDK 3.7.0+、知识库 v1.1 复核于 2026-07-04）。

基础参数：

  • Is Active：控制约束是否参与评估。
  • Weight：整体权重，取值范围 0-1。
  • Aim Vector：控制以哪条轴朝向源。
  • Up Vector：控制向上轴。
  • World Up Type：世界向上的参考方式，五种选项——Scene Up（场景 Y 轴）、Object Up（指定对象的向上方向）、Object Up Rotation（局部空间）、Vector（世界空间向量）、None（无）。

Constraint Settings：

  • Rotation At Rest：权重为 0 时约束呈现的旋转基准。
  • Rotation Offset：应用在结果上的旋转偏移。
  • Lock：锁定 At Rest 和 Offset 设置。
  • Freeze Rotation Axes：冻结特定旋转轴，被冻结轴不参与驱动。

VRCLookAtConstraint 与 Aim Constraint 的取舍：固定正 Z 轴省去方向定制、仅保留 Roll 翻滚控制

结论：VRCLookAtConstraint（注视约束）是简化版的 Aim Constraint——固定以正 Z 轴对准源，省去 Aim Vector、Up Vector 等方向定制参数，只保留翻滚（Roll）控制，适合视线注视、简单朝向跟随等不需要精细方向定制的场景（来源：creators.vrchat.com/common-components/constraints/ §2.2，official，SDK 3.7.0+、知识库 v1.1 复核于 2026-07-04）。

参数清单：

  • Is Active：控制约束是否评估。
  • Weight：整体权重，取值范围 0-1。
  • Use Up Object：是否使用单独的对象来控制翻滚。
  • Roll：绕 Z 轴的角度，在没有使用 Up Object 时生效。
  • World Up Object：控制翻滚所参照的目标对象。

翻滚二选一规则：未启用 Use Up Object 时用 Roll 参数控制绕 Z 轴角度；启用后由 World Up Object 指定控制翻滚的对象。

VRCParentConstraint 参数与多源偏移规则：Position/Rotation 双组 At Rest 加 Offset，每源独立配置

结论：VRCParentConstraint（父约束）移动并旋转目标 Transform 使其如同源的子对象，适合让饰品或道具整体跟随某一骨骼或物体；当约束配置多个源时，各源各自的 Position/Rotation Offset 相互独立、互不影响，需分别调整（来源：creators.vrchat.com/common-components/constraints/ §2.3，official，SDK 3.7.0+、知识库 v1.1 复核于 2026-07-04）。

基础参数：Is Active 控制约束是否评估；Weight 整体权重 0-1。

Constraint Settings：

  • Position/Rotation At Rest：静止时的位置/旋转基准。
  • Position/Rotation Offset：位置/旋转偏移量。
  • Lock：锁定上述设置。
  • Freeze Position/Rotation Axes：冻结特定位置/旋转轴。

多源要点：每个源的偏移是独立设置的——不是所有源共用一组数值；为不同源配不同偏移可实现一个约束按权重混合跟随多个目标。

VRCPositionConstraint 用法与参数：只平移跟随不继承旋转缩放，Freeze Position Axes 支持部分轴跟随

VRCRotationConstraint 用法与参数：只转向跟随位置独立，Freeze Rotation Axes 支持部分轴旋转跟随

结论：VRCRotationConstraint（旋转约束）改变目标 Transform 的旋转使其匹配源的旋转，适合只需要转向跟随而位置保持独立的场景（来源：creators.vrchat.com/common-components/constraints/ §2.5，official，SDK 3.7.0+、知识库 v1.1 复核于 2026-07-04）。

Target Transform 挂 A 驱动 B：约束组件可集中管理，但目标不能运行中用 Animation 切换

约束1 (臀部) → 约束2 (膝盖) → 约束3 (脚)
     深度 1        深度 2        深度 3

优化建议：减少最长约束链的长度；关注最长链而非链的总条数——总条数影响 Count，最长链决定 Depth。

结论：Unity Constraints 可能导致 Avatar 的 Constraint Depth（约束链深度）被高估，使性能分类结果看起来比实际更差；处理方法是打开 SDK Control Panel 使用 Auto Fix，把 Avatar 上所有 Unity Constraints 转换为 VRChat 约束（来源：creators.vrchat.com/common-components/constraints/ 性能章节，official，源文档 v1.0（2026-06-05））。

触发判断：当性能统计中的约束深度明显高于实际搭建的约束链长度时，优先怀疑场景里存在未转换的 Unity Constraints。

统计口径补充：Constraint Depth 按最长约束链计算，Constraint Count 也把 Unity Constraints 计入统计——未转换的 Unity Constraints 会同时影响两项指标的口径，Auto Fix 转换后统计恢复统一。

排查顺序建议：先看 Count 是否虚高（有不该存在的约束），再看 Depth 是否虚高（链被算长），最后跑 Auto Fix 收口。

  1. Is Active：约束的激活开关，对应 API 的 IsActive 属性（约束是否正在参与评估）；未启用则约束不求解。
  2. 组件启用状态：确认约束组件及其所在 GameObject 都处于勾选启用状态。
  3. Lock：约束是否锁定，对应 API 的 Locked 属性；注意进入播放模式后约束始终处于锁定状态。
