NDMF 定义与四大特性：非破坏性框架——原始文件保留、组件化、依赖 Modular Avatar、可叠加组合

结论：NDMF（Non-Destructive Modular Framework）是一种非破坏性最佳化框架[FACT]，四大特性：

  1. 非破坏性：原始文件完整保留，最佳化仅在编译时生效；
  2. 组件化：每个优化步骤是独立组件，便于组合；
  3. MA 依赖：大部分工具依赖 Modular Avatar 运行；
  4. 可叠加：可以多个工具组合使用（组合技）。

核心依赖：Modular Avatar（必装，NDMF 核心）与随其自动安装的 Non-Destructive Modular Framework 基础框架[FACT]。

实用含义[INFERENCE]：非破坏性机制把最佳化推迟到构建期，原始 Prefab/文件不被动，因此可与 Modular Avatar 组件体系共存并叠加多个工具；NDMF 体系的最佳化不破坏原始档案，且支援用 Modular Avatar 穿的衣服。例外：个别社区工具（如 Upload-without-preCheck）不在 NDMF 官方框架内但同属其生态。

NDMF 核心与最佳化工具清单及 VPM 地址：LAC 全自动纹理压缩、AAO 合并优化、lilAvatarUtils 检测、TexTransTool Atlas 化、MA2BT 层压缩

结论：NDMF 生态把优化工具集中到 VPM 体系，初次导入后需在 Settings > Packages 启用[FACT]。

NDMF 内部同一阶段顺序（2026 更新）：

1. Modular Avatar（穿脱服装）
2. MA2BT（MA 响应式层 → Direct BlendTree）
3. Avatar Compressor (LAC)（自动纹理压缩）
4. Avatar Optimizer (AAO)（合并 Mesh/Bone/PhysBone）

6. Meshia / 其他减面工具（按需）

原因：MA2BT 强制 seq.AfterPlugin(“nadena.dev.modular-avatar”)，必须在 MA 之后；它处理的是 Animator 层结构（与贴图无关），顺序可与 LAC 互换，推荐靠前让后续工具基于已合并的 Animator 层工作[FACT]。LAC 在 AAO 之前，因为 AAO 的 Trace & Optimize 基于「贴图状态」决策 Skinned Mesh 与 PhysBone 合并，先压缩贴图能让 AAO 看到最优贴图状态[FACT]。

风险与例外：Fury 与 MA 互相不知道对方做了什么，容易出错，思路是完全理解两者各自的处理区块、避免重叠；不使用 Fury 或不做优化时相应步骤可省略。该顺序为社区实操经验，非官方接口契约[UNKNOWN]。

lilAvatarUtils 性能指标体系：PhysBones 5 指标（Collision=Bones×Colliders）+ Lighting 6 环境模式 + Safety 未应用 Shader 预览

结论：lilAvatarUtils 提供成体系的性能检测指标[FACT]。

PhysBones 5 个性能指标（官方用途：识别对 Performance Rank 影响大的 PB、发现可整合的同根同设定 PB）：

# 字段 含义 性能影响
1 Bones PhysBone 计算的骨骼数 数量越多成本越高（核心指标）
2 Colliders 碰撞检测的碰撞器数 影响碰撞计算频率
3 Collision 碰撞计算总数 = bones × colliders 值越大负载越高
4 Multi Child Type 多子骨骼方向计算方式 算法选择影响性能（Polar 消耗大）
5 Parent 父对象 同一父级且设定相近的 PB 可考虑合并

Lighting 6 种环境模式（LightingTestGUI）：No light（测自发光/Emission）、Overexposure（测高光/曝光溢出）、In Shadow（测阴影表现防黑脸）、Spot Light（测聚光细节/轮廓光）、3 Spot Lights（测复杂舞台光）、Custom（复现特定 World 光照）。

Safety 模式预览（原 VRCD 文档拼写 Safty 为笔误，正确为 Safety）：预览 VRCSDK Safety 下未应用 Shader 的 Avatar 表现——客户端低性能模式会关闭部分 Shader，可提前预览 Quest 等低端客户端表现，避免「特定 Shader 关掉就崩坏」的设计[FACT]。

协作工作流[INFERENCE]：lilAvatarUtils 诊断高成本 PB → AAO Merge PhysBone 自动合并 → lilAvatarUtils 复验。Polar 模式的具体消耗差异无量化数据[UNKNOWN]。

辅助窗口操作规则：Actual Performance Window 看 NDMF 编译后真实效能；AvatarUtils 修改后必须按 Apply 才生效

结论：NDMF 非破坏型优化下，查看编译后状态与批量修改需专用窗口[FACT]。

Actual Performance Window：由于 NDMF 是非破坏型最佳化，VRCSDK 只显示编译前状态（通常 Very Poor）。启用步骤：

1. 功能列 Tools > anatawa12's gist selector
2. 勾选 ActualPerformanceWindow 后点击 Apply Changes
3. 功能列 Tools > anatawa12's gist
4. 勾选 Compute actual Performance on Play

进入 Play-mode 即可查看编译后真实效能。

AvatarUtils 窗口（Tools > AvatarUtils，拖入 Avatar 查看）：核心规则是修改属性后必须按 Apply 才会一次性应用所有更改——不按 Apply 修改不生效[FACT]。三按钮分工：Apply 批量应用所有修改；刷新查看 Apply 后最新状态；Revert 放弃未应用的修改。搜索区输入值后超过阈值的项变红，勾选 Filters 复选框只显示红色（超标）项以快速定位优化目标；多数页面底部 Total 显示该类资源总规模（如贴图总大小、材质总数）。

典型工作流[INFERENCE]：拖入 Avatar → 各 Tab 查看（超阈值变红）→ 勾 Filters 只看红色项 → 修改或 Replace 批量替换 → 按 Apply 一次性应用 → 退出前刷新确认。（个别 Tab 无 Total 时以其页面实际布局为准。）

如梦 VRC 工具箱 MMD 动作转换九步流程：VMD+PMX 生成配置 → Action 层导入 → Locomotion 配对 → FX 层音乐开关

结论：如梦 VRC 工具箱（v1.2.5，作者如梦Nya，https://gitee.com/cmoyuer/vrchat-avatar-toolkit/releases ）可把 MMD 动作转换为 VRChat Avatar 可用[FACT]。

完整工作流：

1. 打开 VRC 工具箱，顶部选择 "VRC工具箱 - MMD动作转换"
2. 拖入 MMD 动作文件（.vmd）
3. 拖入 MMD 模型（.pmx）
4. 点击 "生成配置文件"
5. 调整动画方向：跟变换旋转 → 原始
6. 在 Avatar Animator 的 Action 层导入动画
7. 配置 Locomotion Control 配对
8. 在 FX 层配置音乐开关
9. 转换后 CTRL+D 复制原模型、隐藏原模型、将动画拖到新模型、点击播放测试

转换特性与失败处理：可不带 MMD 模型转换动作，但有些动作会变怪——建议带上 .pmx 模型防止动作失真[FACT]。
