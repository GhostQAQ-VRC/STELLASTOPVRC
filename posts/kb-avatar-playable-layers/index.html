知识库 avatar

Playable Layers 将 Avatar 功能分离到独立动画层

结论：Playable Layers 是将 Avatar 功能分离到独立动画层的机制，可用于跑步、跳跃、点赞、微笑、摇尾巴等功能。[COMMUNITY] 使用前需要掌握 Unity Animator Controller、Avatar Mask 与 Blend Trees 三项基础知识。[COMMUNITY] 它是 VRChat Avatar 动画的层次化组织方式，与 Unity Animator 及 Avatar 动画系统直接相关。[COMMUNITY]

Avatar 3.0 是 5 个 Playable Layers + Expression Menu + Parameters 的参数驱动系统

结论：Avatar 3.0 是由 5 个 Playable Layers（Base/Additive/Gesture/Action/FX）加 Expression Menu 与 Expression Parameters 组成的参数驱动系统，Generic Avatar 只有 Base/Action/FX 三层（Additive、Gesture 为 Humanoid 专用）。[COMMUNITY] VRChat 不使用 Animator 的 Controller 字段，而是通过 VRC Avatar Descriptor 配置这些层；子 GameObject 的 Animator 仍用自己的 Controller。[COMMUNITY] Generic Avatar 不能使用 Expression Parameters 与 State Behaviours 等 AV3 功能，除非满足特定 FBX 导入要求；如不需要 AV3 功能，可在 root Animator 中直接使用动画 Controller。[COMMUNITY]

Avatar 2.0 用 Gesture Override 单层，3.0 用参数驱动多层系统

结论：Avatar 2.0 与 3.0 在控制系统、动画层与菜单控制上差异显著：2.0 用 Gesture Override 控制、只有单层动画、菜单有限、复杂度低；3.0 改用 Animator Parameters+Gesture 控制、提供 5 个 Playable Layers 与完整 Expression Menu、可自定所有层，因此灵活性和复杂度都更高（需理解状态机）。[COMMUNITY] 两者的 Gesture Toggle 行为也不同：2.0 控制 Gesture Override，3.0 控制 Gesture Animator Parameters。[COMMUNITY]

Humanoid Avatar 有 5 个 Playable Layers，Generic 只有 Base/Action/FX 3 层

结论：Humanoid Avatar 使用 5 个 Playable Layers：Base（基础运动层）、Additive（叠加层）、Gesture（手势层）、Action（动作层）、FX（特效层）；Generic Avatar 只有 Base/Action/FX 3 层，没有 Additive 与 Gesture。[COMMUNITY] 因此面向尾巴、耳朵等非人形骨骼的动画在 Generic 上同样依赖 Gesture 层而非 Additive 层。[COMMUNITY]

Playable Layers 按 Base→Additive→Gesture→Action→FX 顺序应用，FX 优先级最高

结论：Playable Layers 按 Base→Additive→Gesture→Action→FX 顺序应用，优先级 FX 最高、Base 最低。[COMMUNITY] 示例：若 Additive 动画骨骼（权重 1.0），然后 Action 也动画同一骨骼（权重 1.0），则 Action 优先——层级按顺序叠加，后应用（优先级更高）的层覆盖先应用的层。[COMMUNITY]

Base Layer 是响应移动的常驻基础运动层

结论：Base Layer 是始终播放的基础运动层，负责响应移动（locomotion），涵盖行走、跑步、跳跃、跌落、蹲下等动作，且只影响 Transform、需用 Avatar Mask 限定影响范围。[COMMUNITY] 注意：在此层添加内容需要重新定义 locomotion 动画状态，非常复杂。[COMMUNITY]

Additive Layer 仅用于人形骨骼，非人形骨骼应放 Gesture 层

结论：Additive Layer 在 Base 层已有基础上叠加动画（如呼吸动画），仅用于人形骨骼；非人形骨骼（尾巴、耳朵等）应改用 Gesture 层。[COMMUNITY] 它始终为 Additive 混合模式，骨骼在 locomotion 期间移动时动画会叠加其上；另外第一个 Additive 层的 Avatar Mask 会被忽略（内部屏蔽用途）。[COMMUNITY]

Gesture Layer 用于底层动画之上的特定部位动画与非人形骨骼动画

结论：Gesture Layer 用于在播放底层动画的同时作用于特定身体部位，支持手势触发（Hand 或 Expression Menu）、闲置动画（尾巴摇摆、翅膀拍动、耳朵移动等）与非人形骨骼动画。[COMMUNITY] 要求只影响 Transform，并使用 Avatar Mask 限定目标部位；这是它与 Additive 层的关键分工差异。[COMMUNITY]

Action Layer 默认混合到零，必须用 Playable Layer Control 混入并混回

结论：Action Layer 的动画完全覆盖其他层的骨骼动画，类似 AV2 Emotes。[COMMUNITY] 三条重要规则：默认混合到零；在 Action 层做任何事之前，必须使用 Playable Layer Control 状态行为将层混合上来；完成时必须混合回零。[COMMUNITY]

FX Layer 处理所有非 Transform 动画并复制到镜像克隆

结论：FX Layer 负责处理所有非 Transform 的动画，并且全部复制到镜像克隆（这点与其他层不同）。[COMMUNITY] 它支持启用/禁用 GameObject、组件修改、材质切换、Shader 动画、粒子系统动画与 Blend Shape 动画，由菜单参数（Toggle、Button、Slider）驱动。[COMMUNITY] 注意：不建议在 FX 层动画 Transform；第一层 FX 的默认 mask 会禁用所有人形肌肉但启用所有 GameObject 动画。[COMMUNITY]

附加姿势：T-Pose 定测量，IK Pose 定膝盖弯曲，Sitting Pose 定坐姿视线

结论：Avatar 的三个附加姿势各有用途：T-Pose 用于确定 Avatar 测量（尤其视点位置）、手腕对齐/扭曲与翼展（影响 IPD），其中关节弯曲会影响 Avatar 比例；IK Pose 用于确定主要关节弯曲方向，膝盖规则为脚向外旋转→膝盖向内弯曲、脚向内旋转→膝盖向外弯曲；Sitting Pose 用于坐姿视点校准及坐姿/闲置动画，自定义需大量调整、建议使用过渡状态。[COMMUNITY]

Gesture 中的非肌肉动画 Transform 必须在 FX mask 中禁用

结论：Avatar Mask 存在跨层冲突规则：如果 Gesture 中有非肌肉动画（如 Transform），这些 Transform 必须在 FX mask 中禁用。[COMMUNITY] 典型场景是 Avatar 有尾巴：Gesture 层有尾巴特殊 mask 与另一个全部位 mask 时，需在第一层 FX 创建自定义 mask（禁用所有肌肉、禁用尾巴中所有骨骼、只启用 FX 动画的 Transform）。[COMMUNITY] 另一常见问题解法：GameObject 同时有 Gesture 中的动画 Transform 与 FX 中的效果组件时，创建子 GameObject 放置静态网格或效果，不动画子对象的 Transform、只动画父对象。[COMMUNITY]

VRCFury 组件族：Armature Link/Full Controller/Gestures/Global Collider/Toggle

结论：VRCFury 提供一组 Avatar 自动化组件：Armature Link（服装/道具附加到骨骼）、Full Controller（合并完整 animator/expression menu/parameters）、Gestures（基于手势创建动画）、Global Collider（全局 PhysBone collider 与 Contact sender）、Toggle（菜单切换、按钮、滑块）与 Other（高级功能）。[COMMUNITY] 其 Constraint 用法包括 Cross-Eye Fix：用 rotation constraints 消除眼睛滚动，自动修复 VRChat 引入的眼睛骨骼滚动问题。[COMMUNITY] 重要提示：不要在多个 Playable Layers 中使用相同的 controller，否则可能随 Avatar 功能扩展造成重大问题。[COMMUNITY]

Avatar Animator 由 VRChat Parameters 驱动状态机，无需 Udon 脚本

结论：Avatar Animator 是 VRChat 对 Unity Animator 的特殊封装，由 VRChat Parameters（手势、表情、菜单项，含内置 VelocityMagnitude/GestureLeft/GestureRight/IsLocal 及用户定义的 Expression Parameters）驱动状态机。[COMMUNITY] 工作流为 Expression Menu→Expression Parameter→Playable Layer→State Machine→Animation Clip→Avatar，无需 Udon 脚本，参数自动驱动且 VRChat 自动同步部分参数。[COMMUNITY] 与 World Animator 的核心区别：Avatar 参数驱动、不支持脚本控制、网络自动同步；World 由 Udon/Script 逻辑驱动、开发者自行同步。[COMMUNITY]

各层驱动源与 SDK 示例文件：Base=移动输入、FX=菜单参数

结论：每个 Playable Layer 有不同驱动源与官方 SDK 示例文件：Base 由移动输入驱动（Locomotion 状态机，vrc_AvatarV3LocomotionLayer）；Additive 持续驱动（呼吸等叠加，vrc_AvatarV3IdleLayer）；Gesture 手势触发（手势+Expression Menu，vrc_AvatarV3HandsLayer）；Action 动作触发即 Emotes 完全覆盖（vrc_AvatarV3ActionLayer）；FX 菜单参数驱动（Toggle、Button、Slider，vrc_AvatarV3FaceLayer）。[COMMUNITY] 示例位置为 Packages/com.vrchat.avatars/Samples/AV3 Demo Assets/Animation/Controllers。[COMMUNITY]

四种骨架类型：Humanoid 是 VRChat Avatar 必须，Legacy 已弃用

结论：Unity 骨架有四种类型：Humanoid（最流行、包含人形骨骼列表映射到 Transform、VRChat Avatar 必须）；Generic（类似 Humanoid 但不含所有人形骨骼/肌肉、仅用于创建 Animator 层遮罩、部分支持）；Legacy（不创建 Avatar 骨架、旧 Unity 动画系统、已弃用不应再使用）；None（无骨架、性能最佳、用于非动画网格）。[COMMUNITY] 其中 Humanoid 是 VRChat Avatar 的前提。[COMMUNITY]

Humanoid 关键配置：Optimize Game Objects 移除未暴露骨骼提高性能

结论：Humanoid 有三个关键配置项：Avatar Definition 提供 Copy From Other Avatar（复制其他虚拟形象的骨骼定义）与 Create From This Model（按导入成功与否显示×/✓并提供 Configure 按钮）；Skin Weights 提供 Standard (4 bones，每顶点最多 4 个骨骼组) 与 Custom（可编辑每顶点骨骼数量与最小权重）；Optimize Game Objects 启用后把未在 Extra Transforms To Expose 中启用的骨骼从 FBX 新实例移除、改用内部表示以提高性能，并可在配置菜单选择性暴露骨骼。[COMMUNITY]

Humanoid 配置界面工作流：Mapping 映射 + Muscles & Settings，Apply/Done 前须 T 姿势

结论：Humanoid 配置界面工作流为：点击 Configure 后当前场景关闭（完成后重开），显示 Mapping 与 Muscles & Settings 两部分。[COMMUNITY] Mapping 含 Body/Head/Left Hand/Right Hand 四个子标题与 Mapping（Clear/Automap/Save/Load）及 Pose（Reset/Sample Bind-Pose/Enforce T Pose）下拉；Muscles & Settings 三部分分别预览肌肉组、编辑单个肌肉范围（范围即骨骼可旋转角度，例 -180~180、肌肉值 0.75→右旋转 90 度）与整体设置（Twist/Stretch/Feet spacing/Translation DoF/Muscles→Reset）。[COMMUNITY] 点击 Apply 或 Done 时虚拟形象须处于 T 姿势；用 Revert（撤销退出）/Apply（应用停留）/Done（应用退出）结束。[COMMUNITY]

Generic 骨架通过 Root Node 设置动画根节点；Avatar 类型决定 Playable Layers 层数

结论：Generic 骨架的 Avatar Definition/Skin Weights/Optimize Game Objects 功能与 Humanoid 相同，另有 Root Node 用于设置动画播放的根节点，对应 Base+Action+FX 3 个 Playable Layers；Legacy 骨架同样有 Optimize Game Objects，且额外下拉选择如何导入动画，但仅适用于旧的 Unity 动画系统、已弃用不应再使用。[COMMUNITY] Avatar 类型与层数对应：Humanoid=5 层完整，Generic=3 层（无 Additive/Gesture），Legacy 无对应层。[COMMUNITY]

VRChat 默认本地 Avatar 用 Always Animate、远程用 Cull Update Transforms

结论：Animator Culling Mode 有三种模式：Always Animate（离屏也保持整个 Avatar 动画化）、Cull Update Transforms（渲染器不可见时禁用变换值变化，如启用/禁用 GO、组件、修改 Blendshape，AAP 与触发状态机行为除外）与 Cull Completely（渲染器不可见时冻结整个 Animator）。[COMMUNITY] VRChat 的特殊处理：本地 Avatar→Always Animate，远程 Avatar→Cull Update Transforms，子 GameObject 上的 Animator 不受影响；远程 Avatar 离屏时因此大幅减少计算，本地 Avatar 始终保持响应。[COMMUNITY] 创作者无需修改默认设置，子 GameObject 动画（武器、配件）应使用 Always Animate 保持交互性。[COMMUNITY]

Animator Locomotion Control 必须配对：进入禁用状态加 Disable、退出加 Enable

结论：Animator Locomotion Control 必须配对使用：进入需禁用 Locomotion 的状态（如舞蹈）前加 Disable，退出该状态（如 BlendOut）时加 Enable，缺失任一都会导致模型乱动或无法移动。[COMMUNITY] 仅 Disable 无 Enable→跳舞结束后再也无法移动或转动视角；仅 Enable 无 Disable→游戏中转动或移动时模型也会动。[COMMUNITY] 来源为 yexcadocs 实操经验（self-mmd.md 完整工作流），非官方文档。[COMMUNITY]

Avatar Descriptor Colliders 兼作 Contacts Sender，无需重复添加 Sender

结论：Avatar Descriptor 的 Colliders 具有双重身份：既是物理碰撞体，也是 Contacts Sender（默认参数为 Head、Body、Hand L、Hand R 等）。[COMMUNITY] 因此手动设置 Contacts 时无需重复添加这些部位的 Sender，默认 Colliders 已提供 Sender 功能。[COMMUNITY]

各层典型应用：Base=站蹲趴姿，Action=舞蹈+AFK 三状态，FX=物品开关+参数驱动

结论：各 Playable Layer 有典型应用模式：Base 层用于站姿/蹲姿/趴姿（如 proxy_stand_still 等可替换）；Action 层用于舞蹈与 AFK（AFK 三状态为 Afk Init/AFK/BlendOut）；FX 层用于物品开关与参数驱动（Toggle/Slider/Button 驱动）。[COMMUNITY] 来源为 yexcadocs 实操经验（2026-07-04）。[COMMUNITY]

Interruption Source 决定可被打断的状态顺序；关键路径建议用 Bool/Int 替代 Trigger

结论：Unity 状态机的 Interruption Source 决定哪些状态可被新过渡打断：Current State 表示当前状态可被打断，Next State 表示下一状态可被打断，Current Then Next 与 Next Then Current 表示两种顺序组合。[COMMUNITY] 注意事项：Trigger 在 Unity 状态机中可正常工作，但在 VRChat 中的行为需人工验证（已标记为待证），建议关键路径使用 Bool/Int 替代 Trigger 触发条件。[UNKNOWN]

保持全 Avatar Write Defaults 一致；VirtualLens2 配 Mixed Write Defaults 需手动调整

结论：第三方相机工具（VirtualLens2/VRCLens）与 Write Defaults 相关的处理规则：整个 Avatar 应保持 Write Defaults 一致（全 On 或全 Off），SDK 会检测 Mixed Write Defaults 并发出警告，完整指南参考官方 Write Defaults on States 文档。[COMMUNITY] VirtualLens2 在安装后更改设置或安装中存在 Write Defaults 混合时无法自动确定设置，需手动调整；使用非破坏性设置时，可给带 VirtualLens 设置组件的对象添加 MA 菜单安装器组件来添加与定位菜单项。[COMMUNITY] VRCLens 文档未深入说明 Write Defaults，建议参考官方 Canny 状态。[COMMUNITY]
