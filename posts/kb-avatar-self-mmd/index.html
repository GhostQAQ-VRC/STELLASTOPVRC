自身跳 MMD 概念：在 Avatar 自己身上播放 MMD 舞蹈动画并配合音乐，社区实操方案非官方功能

结论：自身跳 MMD（Self MMD）指在 Avatar 自己身上播放 MMD 舞蹈动画，通常配合音乐一起播放；此方案来自 yexcadocs 的社区实操经验，不是 VRChat 官方文档定义的功能（来源：yexcadocs §自身跳 MMD，community-tested，2026-07-04）。

基本特征：

  • 位置跟随 Avatar 移动。
  • 应用场景是玩家自己或好友的 Avatar。
  • 音频源跟随 Avatar，可选邦骨（挂接）到嘴部骨骼。
  • 复杂度中等——需要 Action 加 FX 双层 Animator 配置。

对照概念：固定世界 MMD 是另一种结构——位置固定在世界、用于场景装饰、音频源固定在世界、复杂度更高（5 空物体结构），两者的转换步骤见 world-fixed-objects 文档。

自身跳 MMD 与固定世界 MMD 四维度对比：位置、应用场景、音频源、复杂度

结论：自身跳 MMD 与固定世界 MMD 是两种不同的实现结构，在位置、应用场景、音频源、复杂度四个维度上都不同（来源：yexcadocs §自身跳 MMD 概述对比表，community-tested，2026-07-04）。

维度 自身跳 MMD 固定世界 MMD
位置 跟随 Avatar 世界固定
应用场景 玩家自己/好友 Avatar 场景装饰
音频源 跟随 Avatar（可邦骨到嘴部） 固定在世界
复杂度 中等：Action + FX 双层 高：5 空物体结构

选型提示：给玩家角色本身加舞蹈选自身跳 MMD；做世界内的演出装饰选固定世界 MMD。固定世界 MMD 的转换与搭建步骤参见 world-fixed-objects 文档的相关章节。

舞蹈动画文件准备：用如梦 VRC 工具箱转换 MMD，「跟变换旋转-依据」必须设为「原始」

结论：自身跳 MMD 的舞蹈动画文件来自 VRC 工具箱（如梦 VRC 工具箱 v1.2.5）对 MMD 舞蹈的转换；转换后必须点击动画文件，把「跟变换旋转-依据」设置为「原始」，否则会出现动画方向错误（来源：yexcadocs §2.1 舞蹈动画文件 + §9.4 动画方向调整，community-tested，工具版本 v1.2.5）。

动画方向调整要点：

  • 操作路径：选中动画文件 → 「跟变换旋转-依据」→ 选择「原始」。
  • 适用边界：自身跳 MMD 必须调整；固定世界模型可选。
  • 不调整的后果：游戏中舞蹈动画方向错误。

扩展信息：完整转换流程见「如梦 VRC 工具箱 MMD 动作转换流程」块；更早的转换细节依赖 world-fixed-objects 文档相关章节展开。

音乐文件两条要求：已压缩 Vorbis 格式、大小计入 Avatar 200MB 总限制

结论：自身跳 MMD 的音乐文件有两条硬要求：使用已压缩格式（Vorbis）；文件大小计入 Avatar 的 200MB 上传总限制（来源：yexcadocs §2.2 音乐，community-tested，限额口径为 Avatar 200MB 总限制）。

执行要点：

  • 导入 Unity 后把音乐的压缩格式设置为 Vorbis 再使用。
  • 选曲时预留体积余量——音乐越大，留给模型、贴图、其他音频的空间越小。

风险提示：超出 200MB 总限制会导致 Avatar 无法上传；大体积音乐优先考虑裁剪时长或降低码率。

音频源配置三步：空物体挂 Audio Source（Spatial Blend=1）、可选邦骨 Head 骨骼、FX 层动画控制开关

结论：自身跳 MMD 的音频源按三步配置——创建空物体并添加 Audio Source 组件、可选把音频邦骨到嘴部骨骼、用 FX 层动画控制 AudioSource.enabled 实现开关（来源：yexcadocs §3 音频源配置，community-tested，2026-07-04）。

第一步·创建空物体与参数：

  1. 在模型上创建空物体（命名如 Audio_Music）。
  2. 添加 Audio Source 组件。
  3. 推荐参数：AudioClip=音乐文件；空间混合 Spatial Blend=1；多普勒级别 Doppler Level=0；音量衰减 Volume Rolloff=线性衰减；最大距离 Max Distance=20（可调）。

第二步·音频邦骨（可选）：作者习惯把音频邦骨到嘴部——将 AudioSource 拖到 Head 骨骼下作为子物体，音频即跟随头部。

第三步·音频开关：通过 Animator 动画控制 AudioSource.enabled；录制开关动画参考 FX 层物品开关流程。

Action 层配置：Dance_State 接入 Prepare Standing 后状态链并加 Animator Locomotion Control=Disable

结论：自身跳 MMD 在 Action 层接入舞蹈：沿 Entry → WaitForActionOrAFK → Prepare Standing 状态链，任选一个过渡后的状态作为 Dance_State 放入舞蹈动画，并给它添加 Animator Locomotion Control 组件且设 Locomotion Control=Disable（来源：yexcadocs §4.1 Action 层配置，community-tested，2026-07-04）。

分步操作：

  1. 进入 Action 层，定位 Entry → WaitForActionOrAFK → Prepare Standing 链路。
  2. Prepare Standing 后连接 8 个过渡，任选其一后的状态（命名如 Dance_State）。
  3. 将该状态的 Motion 替换为舞蹈动画。
  4. 添加组件 Animator Locomotion Control，设置 Locomotion Control = Disable。⚠️ 不设置会导致游戏中转动或移动时模型也跟着动。
  5. 检查过渡条件：进入条件如 VRCEmote == 1，退出条件如 VRCEmote != 1，关闭退出时间。
  6. 下一状态 BlendOut Stand 也添加 Animator Locomotion Control 并设为 Enable。⚠️ 不设置会导致跳舞结束后再也无法移动或转动视角。

完整状态链：Entry → WaitForActionOrAFK → Prepare Standing → Dance_State（Locomotion=Disable）→ BlendOut Stand（Locomotion=Enable）。

FX 层配置五步：VRCEmote Int 参数、权重 1 图层、音乐开关状态对、关退出时间、录音频启停动画

结论：自身跳 MMD 的音乐开关放在 FX 层实现：添加 Int 参数 VRCEmote，新建权重为 1 的图层，用「VRCEmote == 1 打开 / VRCEmote != 1 关闭」的状态对驱动音频启用与禁用动画（来源：yexcadocs §4.2 FX 层配置 + §5.1 数值配置，community-tested，2026-07-04）。

分步操作：

  1. 添加 Int 型参数命名为 VRCEmote——它是 VRChat 默认参数，通常已存在；若未添加则以 Int 类型新建。
  2. 新建图层，权重设为 1。
  3. 创建音乐开关状态对：打开状态条件 VRCEmote == 1；关闭状态条件 VRCEmote != 1。
  4. 关闭两个过渡的退出时间。
  5. 录制音频启用/禁用动画（控制 AudioSource.enabled）并填入对应状态。

配套关系：菜单侧用 Toggle 把 VRCEmote 置 1 即触发 Action 层舞蹈与 FX 层音乐同时启动。

菜单配置：VRCEmote 用 Toggle 控件 Value=1 绑定舞蹈开关

结论：自身跳 MMD 的表情菜单入口是一个 Toggle 菜单项——Type 为 Toggle、Parameter 为 VRCEmote、Value 为 1，与 Action 层进入条件 VRCEmote == 1 对应（来源：yexcadocs §5 参数与菜单，community-tested，2026-07-04）。

配置项对照：

  • Type：Toggle。
  • Parameter：VRCEmote。
  • Value：1（勾选时写入的数值）。

参数背景：VRCEmote 是 VRChat 默认参数，通常已存在于 Avatar 参数表中；如缺失则以 Int 类型添加后再绑定菜单。勾选菜单后 Action 层切入舞蹈状态、FX 层同步开启音乐；取消勾选走 VRCEmote != 1 退出链返回待机。

Animator Locomotion Control 配对铁律：Dance_State 进 Disable、BlendOut Stand 出 Enable，缺一后果严重

结论：自身跳 MMD 中 Animator Locomotion Control 必须「进 Disable、出 Enable」成对出现——跳舞状态 Dance_State 设 Disable，退出状态 BlendOut Stand 设 Enable；缺失任何一侧都会导致移动失控（来源：yexcadocs §6.1 关键技术点 + §4.1，community-tested，2026-07-04）。

状态 Locomotion Control 设置
准备跳舞（Dance_State） Disable
退出跳舞（BlendOut Stand） Enable

错误后果对照：

  • 缺失 Enable → 跳舞结束后「再也无法移动或转动视角」。
  • 缺失 Disable → 游戏中转动或移动时模型也会跟着动。

证据边界：此配对规则为 yexcadocs 记录的社区共识，仍需结合 VRChat 官方 Animator 文档验证；同主题警告另见 playable-layers 文档 §10.1。

VRChat 上传规则：出场动画特效不得包含 Script 组件——平台不允许上传脚本文件

结论：出场动画中使用的特效必须不包含 Script 组件，原因是 VRChat 平台不允许上传脚本文件；删除脚本后若特效表现异常，只能更换特效（来源：yexcadocs §6.2 + §8.1 特效处理，community-tested，2026-07-04）。

处理方式：

  1. 检查特效预设内是否含 Script 类组件。
  2. 删除 Script 组件后再用于出场动画。
  3. 删除后特效异常（如粒子逻辑依赖脚本）则直接换一个无脚本特效。

适用范围提醒：这条规则针对上传内容中的特效组件；与「动作出场动画失效改用特效/物品出场」的替代策略配合使用。

Unity 默认 60 帧/秒换算：动画秒数 = 帧数 ÷ 60，240 帧等于 4 秒，Animation 窗口查帧数

结论：Unity 默认动画帧率为 60 帧/秒，动画时长按「帧数 ÷ 60 = 秒数」换算，例如 240 帧 = 4 秒；帧数可在 Animation 窗口查看（来源：yexcadocs §6.3 Unity 默认 60 帧/秒，community-tested，口径基于 Unity 默认工程设置）。

常用换算示例：

  • 60 帧 = 1 秒。
  • 120 帧 = 2 秒。
  • 240 帧 = 4 秒。

实践用途：录制出场动画、估算舞蹈片段长度时用此换算预估秒数。

[UNKNOWN] 不同 Unity 工程可修改帧率设置，非默认 60 帧/秒的工程此换算不成立；本页假定默认值。

[UNKNOWN] 动作动画不能做进场动画（切换模型时执行追踪器重置）——社区个人理解，标记 [待证]

[UNKNOWN] 社区观点（yexcadocs 作者个人理解）：动作动画不能用作进场动画，作者原话为「因切换到该模型时会执行追踪器重置」；此说法在源文档中即被标记为 [待证]，尚无 VRChat 官方资料证实（来源：yexcadocs §6.4 动作不能做进场动画，unknown，2026-07-04）。

替代方案（同为社区经验）：若出场动作失效（疑似追踪器重置问题），改用特效或物品出场动画，不动用动作动画。

使用边界：「追踪器重置」的具体机制细节未在源文档说明，需以 VRChat 官方资料查证为准；引用本块结论前应注明其为存疑观点。

顺序播放音乐参数组合：Music_Start（Bool 开关）+ Music（Int 选曲）+ Next（Bool 下一首）与三层菜单设计

结论：自身跳 MMD 的顺序播放音乐用三个参数组合实现——Music_Start（Bool，播放开关）、Music（Int，选择歌曲）、Next（Bool 可选，下一首按钮），菜单按简单开关、显示当前歌曲子菜单、下一首按钮三层设计（来源：yexcadocs §7.1 顺序播放 + §7.3 通用要点，community-tested，2026-07-04）。

参数组合：

参数 类型 用途
Music_Start Bool 播放开关
Music Int 选择歌曲
Next Bool（可选） 下一首按钮

菜单设计：

  • 简单开关：Toggle，Parameter = Music_Start。
  • 游戏中显示当前歌曲（子菜单）：Toggle，Parameter = Music_Start，再加多个 Toggle，Parameter = Music（值 1-N 对应各歌曲）。
  • 下一首：Button，Parameter = Next。

通用要点：顺序/倒序/随机都通过不同 Music 值组合实现，同一思路可扩展到动画/招式的随机播放。

随机播放音乐实现：Music 多值选曲加 Music=0 特殊值触发随机切歌

结论：自身跳 MMD 的随机播放音乐在顺序播放基础上简化实现——保留 Music_Start（Bool，播放开关）与 Music（Int，选择歌曲）两个参数，把顺序播放改为多个 Music 值，并约定一个特殊值（如 Music = 0）用于随机切歌（来源：yexcadocs §7.2 随机播放，community-tested，2026-07-04）。

实现要点：

  1. 参数只留 Music_Start 加 Music 两项，无需 Next 按钮。
  2. 各歌曲映射到不同 Music 数值。
  3. 约定特殊值（Music = 0 或其他未被歌曲占用的值）代表「随机切歌」。
  4. 游戏中点击任意歌曲条目即完成切换。

扩展性：同一套 Music 多值机制同样支撑顺序与倒序播放，区别只在菜单排列与切换逻辑的组合方式。

出场动画实装两型：特效去脚本关循环直放模型上、物品出场走 FX 层隐藏/显现动画对

结论：出场动画有两种实装路径——特效出场（关闭 Looping、剔除 Script 组件后挂在模型上直接上传）与物品出场（隐藏物体录「打开」动画，FX 层建隐藏/显现状态对）（来源：yexcadocs §8.1 特效处理 + §8.2 物品出场动画，community-tested，2026-07-04）。

特效出场动画步骤：

  1. 关闭特效循环（Looping = false）。
  2. 删除 Script 组件（特效不能包含 Script 组件；删除后异常则换特效）。
  3. 放在模型上。
  4. 上传。

物品出场动画步骤：

  1. 动画准备：将物体隐藏，录制「打开」动画（物体显现）。
  2. FX 层配置：新建图层，权重 = 1。
  3. 默认状态（物体隐藏）拖入隐藏动画。
  4. 创建空状态（物体出现）拖入打开动画。
  5. 过渡关闭退出时间，时间长度自定。

动作出场动画双层驱动：Action 层 Start 参数链加 FX 层 Default→Hide→Start 结构，0.1/0.2 过渡时间各有含义

结论：基于动作的出场动画由 Action 层与 FX 层双层驱动，共用 Bool 参数 Start：Action 层负责从待机切入动作动画并在结束时用 Parameter Driver 复位 Start；FX 层按 Default → Hide → Start 结构先隐藏模型再放行动作，其中 0.1 秒过渡等待追踪器重置、0.2 秒过渡衔接站立起手（来源：yexcadocs §8.3 动作出场动画，community-tested，2026-07-04）。

前提：创建 Bool 参数（如 Start）。

Action 层配置：

  1. 过渡 WaitForActionOrAFK → Prepare Standing：条件 Start = true，取消勾选退出时间。
  2. 动作动画状态：Motion = 动作动画；Prepare Standing → 动作动画条件 Start = true 无退出时间；动作动画 → BlendOut Stand 有退出时间 = 1 无条件。
  3. BlendOut Stand 添加组件 VRC Avatar Parameter Driver，Parameter Start = false。

FX 层配置：

  1. 参数 Bool Start 与 Action 层同名；新建图层权重 = 1。
  2. 图层结构 Entry → Default → Hide → Start（Default 模型可见；Hide 隐藏动画；Start 空状态）。
  3. 过渡 Default → Hide：无条件，退出时间 0.1（等待追踪器重置）。
  4. 过渡 Hide → Start：无条件，退出时间 0.2（站立到动作过渡）。
  5. Hide 状态添加 VRC Avatar Parameter Driver，Parameter Start = true。

时间解释：0.1 秒等待模型重设追踪器完成；0.2 秒为站立到动作动画的起始时间；两者均可自行调整。

如梦 VRC 工具箱 v1.2.5 的 MMD 动作转换六步：选 MMD 动作转换页、拖入 vmd/pmx、生成配置文件

结论：如梦 VRC 工具箱 v1.2.5（gitee.com/cmoyuer/vrchat-avatar-toolkit 发布，作者 B 站账号如梦Nya）把 MMD 动作转为 VRChat 可用动画的流程共六步：打开工具箱 → 选择「VRC工具箱 - MMD动作转换」→ 拖入 vmd 动作文件 → 拖入 pmx 模型（可省略但建议带上）→ 点击「生成配置文件」→ 等待生成（来源：yexcadocs §9.1 + §9.2，community-tested，工具版本 v1.2.5）。

分步操作：

  1. 打开 VRC 工具箱。
  2. 顶部选择「VRC工具箱 - MMD动作转换」。
  3. 拖入 MMD 动作文件（vmd）。
  4. 拖入 MMD 模型（pmx）——可不拖入，建议带上以提高还原度。
  5. 点击「生成配置文件」。
  6. 等待生成完成。

来源信息：工具发布页 https://gitee.com/cmoyuer/vrchat-avatar-toolkit/releases；作者 B 站账号为如梦Nya。

MMD 转换工作流三条技巧：建议带上 pmx 模型、CTRL+D 复制原模型测试、「跟变换旋转-原始」防方向错

结论：如梦 VRC 工具箱转换 MMD 动作有三条实操技巧：尽量带上 MMD 模型参与转换、复制原模型再试动画以防污染原资产、转换后把动画文件的「跟变换旋转-依据」设为「原始」（来源：yexcadocs §9.3 工作流技巧 + §9.4 动画方向调整，community-tested，2026-07-04）。

技巧一·建议带模型：可不带 MMD 模型直接转换动作，但部分动作会变怪，建议带上 pmx 模型。

技巧二·复制原模型测试：在层级中 CTRL+D 复制原模型 → 隐藏原模型 → 将动画拖到新模型 → 点击播放测试，避免错误操作破坏原模型。

技巧三·动画方向调整：点击动画文件，「跟变换旋转-依据」选择「原始」；固定世界模型可选此项，自身跳 MMD 必须设置，否则动画方向错误。

自身跳 MMD 故障排除速查表：乱动/无法移动/音乐不播/方向错误/特效失效/出场失效六症对照

结论：自身跳 MMD 六类常见故障各有明确原因与修法，核心高频项是 Animator Locomotion Control 的 Disable/Enable 缺失（来源：yexcadocs §10 故障排除，community-tested，2026-07-04）：

问题 原因 解决方案
跳舞时角色乱动 缺 Locomotion Disable 在动作状态添加 Locomotion Control = Disable
跳舞后无法移动 缺 Locomotion Enable 在 BlendOut Stand 添加 Locomotion Control = Enable
音乐不播放 音频源未启用 FX 层动画检查 AudioSource.enabled
动画方向错误 跟变换旋转未设为「原始」 修改动画文件设置
特效失效 包含 Script 组件 删除 Script 组件
出场动作失效 追踪器重置问题 改用特效/物品出场，不动动作

排查入口：先确认症状属于「动或不该动」类（查 Locomotion 配对），再查音乐链路（FX 层开关动画），最后查资产层（方向设置、脚本组件、进场方式）。
