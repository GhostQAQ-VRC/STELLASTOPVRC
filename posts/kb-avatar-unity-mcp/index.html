Unity MCP 工具定位：经 Model Context Protocol 把 AI 助手桥接进 Unity Editor，Editor 级证据唯一授权通道

结论：Unity MCP（仓库名 MCP for Unity）通过 Model Context Protocol (MCP) 把 AI 助手（Claude / Codex / Cursor 等）桥接到 Unity Editor，让助手能够读取并操纵编辑器状态：管理资产、控制场景、编辑脚本、运行测试、做 Profile 与出构建（build）（来源：github.com/CoplayDev/unity-mcp + coplaydev.github.io/unity-mcp，official，v10.0.0）。

能力与非目标：

  • 设计目标：让 LLM 通过统一协议读写 Unity Editor 状态，而非人工复制粘贴。
  • 核心能力域：资产管理 / 场景控制 / 脚本编辑 / 运行测试 / Profile / Build。
  • 非目标：不是 VRChat 专用；不提供运行时、VR、多人或上传证据。

许可与归属：MIT 许可，Aura 赞助维护，官方明确 not affiliated with Unity Technologies（与 Unity Technologies 无隶属关系）。 对本 VRChat 知识库的项目纪律而言，Unity MCP 是「Editor 级证据」（UNITY_RESOLVED 层级的查询/变更）的唯一授权通道，任何该层级的操作都必须经由它完成（参见 avatar-audit-methodology 的证据分层纪律）。

Unity MCP 三层架构：MCP 客户端 → Python 服务端（FastMCP + WebSocket hub）→ Unity C# 插件 MCPForUnity

结论：Unity MCP 架构为典型三层桥接，AI 助手的工具调用沿「客户端 → Python 服务端 → Unity 内 C# 插件」链路传递，最终在 Unity 主线程执行 Editor API（来源：github.com/CoplayDev/unity-mcp + coplaydev.github.io/unity-mcp，official，v10.0.0）。

层 角色 说明
MCP 客户端 入口 Claude Desktop / Codex / Cursor / 本地 LLM，通过 stdio 或 HTTP 传输发出工具调用
Python 服务端 路由 + 会话隔离 FastMCP + WebSocket hub，把请求路由到正确的 Unity 实例并隔离会话
Unity C# 插件 执行端 MCPForUnity，在 Unity 主线程执行 Editor API（场景 / 资产 / 构建等）

数据流：客户端（stdio/HTTP）→ Python 服务端（WebSocket hub，路由 + per-session 会话隔离）→ MCPForUnity → Unity 主线程 Editor API。

Unity MCP 关键机制：多实例路由、per-session 会话隔离、Editor 操作统一回主线程执行

结论：Unity MCP 支持多实例路由（可同时连接多个 Unity 实例并按实例路由请求）、per-session 会话隔离（不同客户端会话互不串扰）、主线程执行（Editor 操作统一回到 Unity 主线程，规避线程安全问题的误报）（来源：github.com/CoplayDev/unity-mcp + coplaydev.github.io/unity-mcp，official，v10.0.0）。

易混淆点辨析：「单实例唯一所有权」是 playbook/项目纪律，不是该工具官方的独占锁——官方明确支持多实例路由 + 会话隔离；引用时必须区分「工具官方能力」与「项目纪律」两个层面。

项目侧选实例纪律：每次操作前重新发现并证实 instance，不沿用旧连接、不以 recency 选实例（与 Unity MCP 证据边界铁律同源，见 avatar-audit-methodology 条目）。
